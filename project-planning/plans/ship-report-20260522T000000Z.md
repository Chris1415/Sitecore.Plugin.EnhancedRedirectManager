## 1. Summary

PRD-004 adds **regex source mode** to redirect authoring and a **Test surface** for in-app simulation of how the Content SDK `RedirectsProxy` would evaluate a URL against the tenant's redirect inventory. Authoring is reorganized: a new **`EditRowModal`** (ADR-0043) replaces the existing PRD-000 inline row-edit affordance in `RedirectMapDetail`, owns only source + destination + Pattern/Regex mode toggle, and enforces save-time regex validity + capture-group cross-check. The Test surface is a secondary "Test" tab on Full Page with a two-column layout (sticky left rail with read-only maps list + URL + Test button; scrollable trace cards on the right). The simulator (`site/lib/redirects/proxy-simulator.ts`) is a verbatim local port of the upstream `RedirectsProxy` match algorithm, including quirks, with **100% parity** against 15 imported upstream test cases + 8 tenant-captured cases (ADR-0038/0042, M2 satisfied). Regex safety via dual time-cap: 100ms `Promise.race` per `regex.test()` + 3-second total wall-clock (ADR-0039). Mode toggle is transient UI state (ADR-0040); Test surface state lifts to `FullPage` so the Test→Manage deep-link works without losing trace state (ADR-0041). **A 2026-05-21 post-implementation simplification** (PRD § 16) deferred 6 originally-planned affordances to Future Opportunities — see § 3 below. **Zero new SDK surfaces**, zero Sitecore template changes, zero extension-point registration changes.
