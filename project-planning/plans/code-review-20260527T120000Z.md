## Findings

### MAJOR

#### M1 — T028 runtime-contrast assertions are structurally vacuous (will trivially pass even if tokens are broken)

**File:** `site/components/full-page/UpstreamDriftBanner.test.tsx` (tests 13–14), `TestSurface.test.tsx` (no contrast assertions at all)
**Category:** Test Quality
**Severity:** Major

The T028 runtime-contrast requirement (task breakdown § 4c-8 and § 10 T028) specifies that `getComputedStyle(element).borderLeftColor` / `.color` must not resolve to `rgb(0,0,0)` — the collapse-failure pattern used to detect undefined CSS variables.

The implemented approach substitutes structural class-name assertions (test 13: "class `drift-banner` is present"; test 14: "SVG in glyph area") instead. These assertions do NOT verify that the Blok Nova CSS variables (`--destructive`, `--destructive-background`, etc.) resolve to non-zero values at test time. The task breakdown explicitly called out the jsdom limitation:

> "If a CSS variable is undefined at test time, `getComputedStyle` returns `currentColor` (which resolves to `rgb(0,0,0)` in jsdom). A test asserting `color !== 'rgb(0, 0, 0)'` catches this collapse."

The substitution was documented in the run manifest (escalation: "T028 contrast: substituted token-class assertion for jsdom getComputedStyle") and flagged by QA pre-implementation (operator_attention entry 2026-05-27T11:00:00Z). However the substitution means the token-collapse failure mode goes undetected.

This is Major (not Critical) because:
1. The structural class assertions do verify the correct CSS classes are applied.
2. The CSS is authored using `var(--destructive)` tokens (verified in globals.css) without hex fallback literals.
3. PRD-005 does not introduce new CSS variables — it consumes pre-existing Blok Nova tokens that are tested by PRD-004 theming tests.
4. The gap was flagged in the manifest; the operator acknowledged it.

**Fix approach (for /test to implement):** Inject the minimal subset of Blok Nova CSS variables (`--destructive`, `--destructive-background`, `--warning`, `--warning-foreground`, `--muted-foreground`) into the jsdom document via a test helper or `vitest.setup.ts` extension, then replace the class-name assertions with `getComputedStyle` assertions per § 4c-8. Reference: `site/app/globals.css` drift section defines the correct token values.

#### m3 — Invalid `eslint-disable-next-line` comment references non-existent rule `react-hooks/set-state-in-effect`

**File:** `site/components/full-page/TestSurface.tsx:132`
**Category:** Code Quality
**Severity:** Minor

```ts
// eslint-disable-next-line react-hooks/set-state-in-effect
```

`react-hooks/set-state-in-effect` is not a real ESLint rule. The `react-hooks` plugin has `exhaustive-deps` and `rules-of-hooks` but not `set-state-in-effect`. This comment does nothing and misleads readers about what ESLint concern it suppresses. The actual pattern (calling `setBannerDismissed` inside a `useEffect`) is intentional and correct per the SSR-safety contract documented inline (hydration mismatch guard). The only real lint rule that could fire here would be `react-hooks/exhaustive-deps` if `setBannerDismissed` were in a deps array, but it isn't.

**Suggested fix:** Replace with a plain explanatory comment, or remove the disable comment entirely since no actual rule fires here.

#### m4 — `compareSnapshot()` silently treats missing-path entries as in-sync

**File:** `site/lib/upstream-drift/sync-helpers.ts:47`
**Category:** Correctness (edge case)
**Severity:** Minor

```ts
if (latestSha !== undefined && latestSha !== file.sha) {
```

When a `watchedFiles` entry has a path that is not present in the `latest` array (e.g. the operator passed an incomplete `latest` input), `latestByPath.get(file.path)` returns `undefined` and the condition short-circuits — the file is treated as in-sync. For the slash command use case this is benign (the slash command always fetches both files). However the semantics are mildly surprising: a missing entry in `latest` is indistinguishable from a matching entry.

The test suite (sync-helpers.test.ts) does not cover this edge case. The task breakdown did not require it either, so this is not a test-contract gap — it is an unspecified edge case that happens to be safe in the current usage pattern.

**Suggested fix for /test to consider:** Either document the "missing = in-sync" contract explicitly in the JSDoc, or change the guard to `if (latestSha === undefined || latestSha !== file.sha)` to treat missing as drifted (more conservative). The latter is safer if this function is reused beyond the slash command. No auto-fix applied — behaviour change decision belongs to operator.
