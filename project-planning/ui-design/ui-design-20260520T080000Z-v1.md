## 1. Design context & assumptions

> ### Post-write amendment 2026-05-20T13:00 (READ THIS FIRST)
>
> After the initial spec was written and the POC was generated, three design pivots were agreed:
>
> 1. **`EditRowModal` replaces inline `RowEditForm` (ADR-0043).** Row editing is now done in a Blok modal (`@blok/dialog`, with `@blok/sheet` documented as alternative) that opens when an operator clicks any row in `RedirectMapDetail`. The modal carries **only** mode toggle, source, inline hint, snippet library, sample tester, destination, and capture chips — `RedirectType`, `IncludeVirtualFolder`, `PreserveQueryString`, `PreserveLanguage` are map-level fields and stay in the existing map-settings UI (unchanged). Save calls existing `lib/sdk/redirects-write.ts`; no new SDK surface.
> 2. **Test surface becomes a two-column layout with a sticky scope picker.** Left rail (~360px, sticky) holds the scope picker (Collection → Site → Map(s) cascading `@blok/select`), URL input, locale dropdown, and Test button. Right area scrolls and renders the trace cards (unchanged anatomy). Below 768px, columns stack vertically and the scope picker becomes a top accordion that auto-collapses after selection.
> 3. **Simulator scope is per-picked-maps, not tenant-wide.** Trace "rows considered" only enumerates rows from picked maps. The empty state's CTA is replaced — the precondition is **scope**, not URL: *"Pick a collection, site, and at least one map to start testing."* Scope picker selection persists to `localStorage["rm-test-picker-v1"]` (ADR-0022 versioned-key pattern); missing IDs reset that level + downstream with a dismissable "previous selection no longer available — pick again" inline message.
>
> The remainder of this spec has been updated to reflect (1), (2), and (3). Any older description of an inline `RowEditForm` extracted from `RedirectMapDetail`, a single-column Test surface, or an `isRegexOrUrl`-prefilled URL CTA empty state is **superseded by the modal + two-column + per-scope picker design**.

- **Audience.** Same operator set as PRD-000/002/003 — site administrators (primary regex authors), migration operators (primary testers), marketers (secondary testers), site administrators debugging operator complaints (secondary testers). All inside the Cloud Portal iframe, evergreen Chromium/Firefox/Safari, light + dark theme, on desk-class displays. PRD-004 adds a new authoring scenario (regex) and a new verification scenario (Test) to people who already know the existing PRD-002 V4 Manage tab.

- **Goals and success criteria (UI-side, tracking PRD § 3).**
  1. The new affordances feel **native to V4 Blok Elevated** — same Geist Sans/Mono stack, same Blok semantic tokens, same hover-lift / glass / hero-clamp grammar. Operators must not perceive a "new screen" — they must perceive an extension of the same workspace.
  2. **Manage / Test segmented control is unmistakable as a top-level tab** (not a chip filter, not a button group) — operators understand it switches the whole working surface.
  3. **Test surface trace is operator-actionable in <30 seconds** for non-match diagnosis (PRD M4). The "rows considered" card answers *"which rule should I have written?"* glanceably.
  4. **Mode toggle is unmistakable as a per-row authoring mode**, not as a filter or display preference. Operator switching to Regex sees the helpers appear; switching back to Pattern sees them collapse — no orphan state.
  5. **Inline hint reads as advisory, not as error.** Muted token color, `role="status"`, one-click "Switch mode" button. Never blocks save.
  6. **Reduced-motion fallback is polished, not broken.** Trace cards stagger-render under default motion; render instantly under `prefers-reduced-motion: reduce` — both look intentional.
  7. **Dark + light + system theme parity.** Every new surface ships AA contrast in both modes — global theme policy.

- **Constraints (binding).**

All new surfaces compose existing utilities from `site/styles/elevated.css` (`.elev-glass-surface`, `.elev-card`, `.elev-eyebrow`, `.elev-btn`, `.elev-hero-text`, `.elev-hover-lift`, `.http-code`, `.glyph`) and tokens from `site/app/globals.css`. **Zero new design variants.** Net-new CSS is utility extension only (e.g. `.fp-tab`, `.test-card`, `.test-card--result`, `.test-card--row`, `.snippet-pill`, `.capture-chip`) — every property composes existing tokens.

Every accent expression composes via `color-mix(in oklch, var(--<token>) <pct>%, transparent)` against Blok semantic tokens (`--primary`, `--info`, `--success`, `--warning`, `--destructive`, `--muted`, `--border`, `--ring`, `--card`, `--background`, `--foreground`, `--muted-foreground`).

## 2. Design direction

### Named direction — "Trace & Tame" (subtle delta on V4 Blok Elevated)

**Trace** because the new Test surface is fundamentally a structured trace of how the runtime would resolve a URL — a stack of cards that walks operators through the pipeline stage by stage, like a debugger session presented as a story, with a **persistent left rail** that pins the scope (which collection, which site, which maps) to the right-rail trace. **Tame** because the new `EditRowModal` and its mode-aware helpers (mode toggle, snippets, capture chips, inline hint) tame the previously-implicit regex authoring flow — operators no longer guess whether the runtime will treat a pattern as URL or regex, and they no longer lose context by drilling into a separate page to edit a row.

Three compositional motifs are net-new versus PRD-000 / PRD-002:

1. **Trace card stack** — numbered stage badge + left-border stage accent + monospace I/O block. Single column on the right side of the two-column Test surface, max-width 880px.
2. **`EditRowModal` overlay** — Blok dialog on a dimmed backdrop, anchored on the Manage tab. Centered card (max-width 720px), `.elev-glass-surface` ceiling, footer with Cancel + Save. Operators see the row "lift up" instead of navigating away.
3. **Two-column Test layout with sticky scope picker** — left rail (`position: sticky`, top:0, width 360px) carries three cascading `@blok/select` instances (Collection → Site → Maps) plus URL input + Locale + Test button. Right column scrolls independently and holds the trace cards. The pinned scope means the trace's "rows considered" always answers the question *"rows considered from where?"* — the operator can see the picked maps at the top-left while reading the result at the right.

The visual move stays intentionally subtle: same hover-lift cards, same gradient-clip hero text, same `--primary`-tinted glow, same Geist Sans/Mono. Every new motif composes from existing tokens; none of them creates a new vocabulary.

- Use **`@blok/tabs` with `variant: "soft-rounded"`** (the rounded-pill variant; see `tabs.tsx` `tabsTriggerVariants`).
  Rationale: the existing `RedirectMapDetail` and `<960px` fallback already use `@blok/tabs` `variant: "line"` (underline-style) for in-card secondary navigation. Using the soft-rounded variant for the **workspace-level** tab control creates a clear visual hierarchy — line tabs = nested/secondary, pill tabs = top-level/primary — without inventing a new primitive.
- **Active pill style:** `data-[state=active]:bg-primary-bg data-[state=active]:text-primary-fg` (already in the Blok variant). Hover: `hover:cursor-pointer`, plus a faint `color-mix(in oklch, var(--primary) 6%, transparent)` background lift via the existing `.elev-hover-lift` semantics applied to the tab list container.
- **Tab list container:** `.elev-glass-surface` modifier with reduced padding (e.g. `px-2 py-1.5`), `rounded-full`, `border` from `--border`. The frosted-glass treatment ties the control visually into the rest of the V4 workspace.
- **"Test" tab label:** plain "Test" + optional dot indicator (`A-UI-2`). The dot is a 6px circle, `background: var(--primary)`, with the same primary-shadow ring as `.elev-eyebrow .dot`. It sits in the upper-right of the tab pill at `top: 0.375rem; right: 0.5rem;` — only when `lastTrace !== null && activeTab !== 'test'`.
- **Cross-fade on switch:** the outgoing panel `opacity: 0; transform: translateY(-4px);` (180ms `var(--v4-premium-ease)`), the incoming panel `opacity: 1; transform: translateY(0);` from `opacity: 0; transform: translateY(4px);`. Reduced-motion: instant swap, no transform.

```
│   ╭─ Snippet library ────────────────────────────────────────────────  ▾ ╮   │ ← @blok/collapsible
│   │ [ ^/ ] anchored start    [ /?$ ] trailing slash    [ \?.*$ ] query strip │ │   open-on-Regex
│   │ [ ^/blog/(.+)$ ] blog migration   [ \.html?$ ] file extension           │ │
│   │ * PM-proposed; pending operator validation in T3                        │ │
│   ╰────────────────────────────────────────────────────────────────────────╯ │
│                                                                               │
│   ╭─ Live sample tester (MVP-deferable; collapsed by default) ─────────  ▸ ╮ │
│   │ (closed)                                                                │ │
│   ╰────────────────────────────────────────────────────────────────────────╯ │
│                                                                               │
│   Destination                                                                 │
│   ┌─────────────────────────────────────────────────────────────────────┐    │
│   │ /blog/$1                                                             │    │
│   └─────────────────────────────────────────────────────────────────────┘    │
│   [ $1 ]  [ $siteLang ]                                                       │ ← capture-group chips
│                                                                               │
│   ────────────────────────────────────────────────────────────────────────    │
│                                                  [ Cancel ]   [ Save row ]    │ ← modal footer
└───────────────────────────────────────────────────────────────────────────────┘

NOTE: RedirectType (301/302/server), IncludeVirtualFolder, PreserveQueryString,
PreserveLanguage are MAP-LEVEL fields — they live in the existing map-settings
UI and are NOT present in this modal.
```

When mode is Pattern, the **Snippet library**, **Live sample tester**, **inline hint** (unless URL-→-regex auto-detect disagrees), and **capture-group chips** are all hidden — the modal body collapses to mode toggle + source + destination + footer.

**Dismiss behavior.** Esc / close button / click on the backdrop. If `source` or `destination` differ from their initial values, prompt *"You have unsaved changes — discard?"* via a `@blok/alert-dialog` confirm before closing.

**Save.** Calls existing `lib/sdk/redirects-write.ts`. No new SDK surface introduced by the modal. On success, modal closes with a Sonner toast *"Row saved."*. On error (invalid regex throw), modal stays open and the inline `SaveErrorMessage` renders under the source input (see § 4.9).

### Key components and patterns

Five new compositional motifs, each composed from existing Blok primitives + existing `elevated.css` utilities:

1. **`@blok/tabs` (soft-rounded variant) as workspace-level segmented control** — Area 1. Uses the existing primitive's existing variant; the only new bit is the optional dot indicator on the Test pill (A-UI-2).
2. **Trace card with numbered stage badge + left-border accent** — Area 2. Composed from `@blok/card` + `@blok/badge` + monospace `<pre>` blocks. Stage color comes from semantic tokens (`--primary` for match/dispatch, `--muted-foreground` for normalize/candidates, `--success` for the result-card match, `--warning` for timeouts, `--destructive` for diagnostic-incomplete, `--info` for pre-filter informational stages).
3. **`@blok/tabs` (line variant) as in-form segmented control** — Area 3 mode toggle. Same primitive, different variant. The full-width treatment is a width override on the `TabsList` (`w-full grid grid-cols-2`). Now lives **inside** `EditRowModal`.
4. **`EditRowModal` (NEW per amendment 2026-05-20)** — Blok dialog overlay opened on row click. Replaces standalone `RowEditForm` page. See § 4.11.
5. **`ScopePicker` (NEW per amendment 2026-05-20)** — three cascading `@blok/select` instances + sticky left rail layout. See § 4.12.

### Critical user flows

#### F1 — Author a regex rule with helpers in the modal (US-R1)

1. Operator clicks a row in `RedirectMapDetail` (any cell — the whole row is clickable).
2. **`EditRowModal` opens** on a dimmed/blurred backdrop. **Mode toggle reads Pattern** (default per FR-A2). Focus moves to mode toggle.
3. Operator clicks the **Regex** pill in the segmented control.
4. Snippet library expands (auto-open on Regex). Capture-group chip strip appears below destination (initially only `$siteLang`).
5. Operator clicks the `[ ^/blog/(.+)$ ]` snippet pill. The pattern is inserted into the source input at the cursor; chip strip grows to `$1`, `$siteLang`.
6. Operator clicks the destination input, types `/articles/`, clicks the `$1` chip → destination becomes `/articles/$1`.
7. Operator clicks **Save row** (modal footer). `new RegExp(source, flags)` succeeds → `lib/sdk/redirects-write.ts` is called → modal closes → Sonner toast *"Row saved."*.

#### F2 — Mode mismatch hint inside the modal (US-R2)

1. Operator clicks a row whose source is `^/legacy/(.+)$`. **Modal opens.**
2. Mode toggle defaults to **Pattern** (FR-A2).
3. `isRegexOrUrl(source) === 'regex'` → the inline hint renders inside the modal: *"This pattern contains regex characters; the runtime would treat it as a regex."* + `[ Switch to Regex → ]`.
4. Operator clicks the hint button → mode flips to Regex, helpers appear inside the modal, no loss of source/destination edits.
5. Hint disappears (manual mode now matches auto-detect).

#### F3 — Save fails on invalid regex; modal stays open (AC-R1.5)

1. Operator (in Regex mode inside the modal) types `^/foo/(.+]$` (typo — unbalanced bracket).
2. Operator clicks **Save row** in the modal footer.
3. `try { new RegExp(...) }` throws. Save is blocked. **Modal stays open.** Source input gets `--destructive` border; error renders below: *"Invalid regex: Invalid regular expression: missing terminating ] for character class."* (Exception message verbatim per AC-R1.5.)
4. Focus moves to source input via `aria-describedby` of the error element.
5. Save button stays enabled (operator can fix-and-retry); the error clears on next keystroke.

#### F4 — Test a URL that matches, with scope picker (US-T1, AC-T1.6)

1. Operator switches to **Test** tab (top-level segmented control).
2. **Left rail:** scope picker visible. If `localStorage["rm-test-picker-v1"]` carries a valid persisted scope (Collection + Site + Map IDs all still resolve), it rehydrates and the operator sees pre-selected picker values. Otherwise the pickers are empty.
3. Operator picks Collection "Marketing" → Site list loads → operator picks "Production" → Map list loads → operator ticks "Blog Migration 2026".
4. Operator types `/old-blog/post-1?utm=foo` into the URL input, leaves Locale at `en`.
5. **Test button enables** (scope ≥ 1 map AND URL non-empty). Operator clicks Test. Button shows spinner; right column renders 4-6 skeleton cards. Left rail scope picker stays visible + sticky.
6. Simulator resolves against only the picked maps; cards stagger-render at 40ms/card (instant under reduced-motion).
7. ResultCard at the bottom of the right column shows **Match · 301**, destination `/blog/post-1`, source row reference, and a primary **`[ Open this rule in Manage → ]`** button.
8. Operator clicks the button → activeTab flips to Manage, the source map is selected in the rail, and **`EditRowModal` opens** focused on the matching row.

#### F5 — Test a URL that doesn't match (US-T2)

1. With Collection + Site + at least one Map already picked on the left rail, operator types `/promo-2025` into the URL input. Clicks Test.
2. Right column trace stack renders normalize → candidates → 8 row-evaluate cards (all "no match", **only from picked maps**) → final no-match result.
3. **"Rows considered" card** is the dominant readable summary: first 5 rows shown collapsed, "Show all 20" expand button, then "+ N more (chunked)" per AC-T2.2. The phrase *"20 rows considered"* now means *"20 rows in the picked maps,"* not *"20 rows in the tenant."*
4. Final result card reads *"No rule matched. Did you mean to add a rule for `/promo-2025`?"* with a secondary outlined button *"[ Add a rule for this URL → ]"* (deep-links to Manage tab → currently-selected map → opens `EditRowModal` in Add mode with the source field prefilled).
5. Operator diagnoses the gap in <30s (PRD M4 success).

#### F7 — Stale persisted scope rehydration *(NEW)*

1. Operator returns to the Test tab after a teammate deleted "Blog Migration 2026" from the Production site.
2. App reads `localStorage["rm-test-picker-v1"]` and attempts to rehydrate the persisted Collection + Site + Map IDs.
3. The Map ID no longer resolves. The Map picker stays empty; an inline `@blok/alert` (info-tone) renders above the empty pickers: *"Previous selection no longer available — pick again."*
4. Operator changes any picker (e.g. picks a different map). The stale-message auto-dismisses on first new picker interaction (default decision for OD-7).
5. Scope is re-persisted via the next valid combination.

#### F6 — Diagnostic incomplete (S10)

1. Operator runs Test against an inventory with 500+ rows, several with catastrophic regex.
2. 3s wall-clock cap fires (ADR-0039 / FR-S5).
3. Trace stops emitting evaluate-row cards. Final card replaces the would-be result card with a **`.test-card--diagnostic-incomplete`** variant: `--warning` accent, copy *"Diagnostic incomplete after 3s — evaluated 184 of 523 rows."* Footer hint: *"Tip: this URL may trigger a catastrophic pattern. Try a simpler URL or check the rows considered for slow-pattern warnings."*

### 4.4 `TraceCard` — generic stage card

**Universal anatomy (every card kind has the same shell).**

```
┌─ TraceCard ─────────────────────────────────────────────────────────────────┐
│ ┃ [N] Stage name · sub-label                                          ▾    │
│ ┃ ┌────────────────────────────────────────────────────────────────────┐  │
│ ┃ │ Input:    <monospace>                                              │  │
│ ┃ │ Output:   <monospace>                                              │  │
│ ┃ └────────────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────────────┘
```

The thick `┃` on the left is the **left-border accent**, color-keyed per stage kind. Stage number badge is a small `@blok/badge` (e.g. `[1]`, `[2]`) in `--neutral` tone. The `▾` is a `@blok/collapsible` trigger for cards that have verbose details (candidate paths > 5; rows-considered cards always collapsible).

**Per-stage variant table.**

| `stage.kind` | Card label | Left-border accent token | Sub-label | Body content | Collapsible? |
|---|---|---|---|---|---|
| `pre-filter` | "Pre-filter check" | `--info` | `check` (e.g. "has-dot") | One-line `note` ("URL contains . → runtime would skip; simulator continues for diagnostic visibility") | No |
| `normalize` | "Normalize" | `--muted-foreground` | — | `Input:` (raw URL) + `Output:` (normalized URL) | No |
| `candidates` | "Candidate paths" | `--muted-foreground` | `locale: <locale>` | bullet list of candidate paths (max 5 visible) | Yes when >5 |
| `evaluate-row` (outcome `match`) | "Evaluate row" | `--primary` (strong) | `<mapName> · row <N+1> · <mode>` | `Pattern:`, `Candidate:`, `Groups:` (if any) | Yes |
| `evaluate-row` (outcome `no-match`) | "Evaluate row" | `--muted` | `<mapName> · row <N+1> · <mode> · no match` | `Pattern:`, `Candidate:` (the one that came closest) | Yes |
| `evaluate-row` (outcome `skipped`) | "Evaluate row" | `--muted` | `<mapName> · row <N+1> · skipped` | one-line `note` explaining why | No |
| `evaluate-row` (outcome `timeout`) | "Evaluate row" | `--warning` | `<mapName> · row <N+1> · timeout` | `Pattern:` + warning copy ("Pattern too slow — runtime would also stall here.") | No |
| `substitute` | "Substitute" | `--primary` | — | `Template:` (with placeholders) + `Resolved:` + `Substitutions:` (each key=value on its own line) | No |
| `flag-effects` | "Apply flags" | `--primary` | — | Three flag badges (`PreserveQS`, `PreserveLang`, `IncludeVF`) — each `on` or `off`; `Transformed URL:` below | No |
| `dispatch` | "Dispatch" | `--primary` (strong) | — | `Redirect type:` (with `.http-code--*` chip) + `Final URL:` | No |

### Accessibility notes

- **Workspace tab control:** Radix Tabs provides `role="tablist"` + `role="tab"` + `aria-selected` + arrow-key navigation out of the box. Selected pill: `data-[state=active]` + visible focus ring on focus-visible.
- **`EditRowModal` (NEW):** Radix Dialog (or `@blok/dialog`) ships `role="dialog"` + `aria-modal="true"` + `aria-labelledby="edit-row-modal-title"` + `aria-describedby="edit-row-modal-desc"` + focus trap + Esc handling + initial focus on the mode toggle. The map-row click target carries `aria-haspopup="dialog"` + `aria-controls="edit-row-modal"`. Focus returns to the originating row on close.
- **`ScopePicker` (NEW):** Each `@blok/select` has a programmatic `aria-label` ("Collection," "Site," "Map") via `<Label htmlFor>`. Cascading-disabled state uses `aria-disabled="true"` + visible "Pick a {parent} first" helper text. Loading state uses `aria-busy="true"`. Error `@blok/alert` is `role="alert"` + named retry button. Stale-localStorage alert is `role="status"` + `aria-live="polite"` — non-intrusive.
- **`EditRowModal` mode toggle:** Same Radix Tabs primitive. Operators using AT hear "Pattern, tab, 1 of 2 selected" / "Regex, tab, 2 of 2 not selected." Arrow keys switch; Enter activates.
- **Inline hint:** `role="status"` + `aria-live="polite"`. Never steals focus. AT users hear the hint announced after their next pause in input.
- **Save error:** `role="alert"` + `aria-describedby` linkage from source input. Focus moves programmatically to the error message on save failure (or to the source input with `aria-invalid="true"` — operator preference; implementation can pick either, but consistency matters). Modal stays open.
- **Snippet pill:** `aria-label="Insert snippet: anchored start (^/)"` — gives blind operators both the human label and the pattern. Buttons, not links.
- **Capture-group chip:** `aria-label="Insert $1 into destination"`. Each chip in a `role="group"` container with `aria-label="Insert capture group"`.
- **Test button:** `aria-label` changes based on state (`"Test this URL"` / `"Testing in progress"`); the spinner is `aria-hidden="true"`. Disabled state has a helper text element (announced via `aria-describedby`).
- **Trace cards:** Each card has `<h3>` semantic heading with the stage name. Collapsibles use `@blok/collapsible`'s native `aria-expanded` + `aria-controls`. Screen reader users can navigate stage-by-stage via heading nav.
- **Result card:** `<h2>` heading "Match" or "No match" or "Diagnostic incomplete" — the dominant result is reachable as the most senior heading in the trace.
- **Test surface tab-switch:** When operator activates the Test tab, focus moves to the first picker (Collection) if no persisted scope; otherwise focus moves to the URL input. When they click "Open this rule in Manage" on a ResultCard, focus moves to the mode toggle of the opened `EditRowModal`.
- **Row-as-click-target (Manage):** Each table row becomes a `<button>` (or `role="button"`) wrapping its cells, with `aria-label="Edit row N: {source}"`. Keyboard activates with Enter/Space. The visible row chrome (border, edit-pencil icon) stays the same; the icon becomes redundant but is kept for visual affordance.
- **Copy as JSON:** Sonner toast announces "Trace copied to clipboard" with `aria-live="polite"`.
- **Locale "Other..." free-text:** the rendered free-text input gets the same `aria-describedby` as the select, plus its own pattern-validation message: "Use the form xx or xx-XX (e.g. en or de-DE)."
- **Reduced motion:** the global `prefers-reduced-motion: reduce` blanket in `elevated.css` covers everything, but the per-rule gates above provide local fallbacks for hover transforms and trace-card reveal.
- **Contrast (verified at spec-time, must be retested in T5):**
  - `.test-card` body monospace text (`color: var(--foreground)` on `background: var(--muted)`) — passes AA in both themes (existing PRD-000 / PRD-002 verification).
  - `.snippet-pill__pattern` (`color: var(--primary)` on light card with primary-tinted background) — passes AA in light; verify in dark with `--primary` → `--color-primary-200` swap (existing dark-mode mitigation already validated for PRD-002 buttons).
  - `.capture-chip` (`color: var(--primary)` on `primary 6%`) — passes AA in light; in dark `--primary` is `primary-200` (light lavender) on a near-black surface — high contrast.
  - `.inline-hint` (`color: var(--muted-foreground)` on muted bg) — borderline; in dark mode `--muted-foreground` is `whiteAlpha-600` on `gray-900` — verify in T5. If <4.5:1, escalate to `--foreground` color for the hint body (`--muted-foreground` only for the glyph and chevron).

## 6. Open questions and handoff

### Open questions (UI-side, on top of PRD § 14 + architecture § 10)

- **OD-1 — Should the inline hint copy mention the auto-detect mechanism by name (`isRegexOrUrl`)?** Default: no. Operators don't need to know the algorithm's name; the copy *"runtime would treat as regex"* is enough. Revisit if T6 smoke shows operators are confused about *why* the hint appears.
- **OD-2 — Should the workspace tab control show a count badge on the Test pill (e.g. "Test · 3" for 3 historical traces)?** Default: no. Only the latest trace is persisted (architecture § 4.3 `lastTrace`). The dot indicator is sufficient.
- **OD-3 — Should the "Open this rule in Manage" CTA on no-match also exist?** Default: yes, as a secondary outlined button reading *"[ Add a rule for this URL → ]"* (deep-links to Manage → currently-selected map → opens RowEditForm in Add mode with source field prefilled). This closes the diagnose-then-fix loop without a Test→Manage→back-to-Test round trip.
- **OD-4 — Capture-group chip ordering when the source has gaps in numbering (e.g. user wrote `$1` and `$3` but only has 2 groups).** The chip strip renders `$1`, `$2`, `$siteLang` based on detected group count. The cross-check error message (AC-R1.6) covers the `$3` reference. Default behavior: chips reflect group count; error message guides operator. Revisit if operators routinely write gap-numbered references.
- **OD-5 — Trace card animation under simulated 3s-cap.** When the simulator hits the wall-clock cap mid-emit, the partial trace stack ends with a `diagnostic-incomplete` stage. Should subsequent cards continue to stagger-render even though the trace is incomplete? Default: yes; the cap is bounded at 3s real-time, so stagger continues for the visible cards. The final `diagnostic-incomplete` card renders with `--warning` accent.
- **OD-6 — Sample URL prefill behavior when first map's first rule has a Regex source.** A regex like `^/blog/(.+)$` is not a usable sample URL — it's a *pattern*. Default: if the first rule's source matches `isRegexOrUrl(...) === 'regex'`, fall back to a hardcoded sample `/sample-url`. Document in the prefill chip: *"No simple URL available; using `/sample-url`."* **Amendment note 2026-05-20:** with the scope-first redesign, prefill is now scoped *per picked map*. Behavior carries: prefill the URL input from the first row of the first picked map; if regex-shaped, fall back to `/sample-url`.
- **OD-7 — Persisted-stale-scope inline message dismissal (NEW per amendment 2026-05-20).** When the operator returns to the Test tab and the persisted `localStorage["rm-test-picker-v1"]` references IDs that no longer resolve on the tenant, an inline info alert reads *"Previous selection no longer available — pick again."* Should the message stay visible until the operator explicitly dismisses it, or auto-dismiss after the first new picker change? **Default decision: auto-dismiss after first new picker change.** Rationale: the message is informational, not blocking; once the operator engages with the pickers they no longer need the prompt, and persistent dismissable alerts add cognitive overhead. Revisit if T5 smoke shows operators miss the alert because they happen to pick something before reading it.
