## 1. Architecture Overview

PRD-004 is a **feature-scoped delta** on the existing Redirect Manager Marketplace app. It introduces two co-shipping surfaces — a per-row Pattern / Regex mode toggle in the row-edit flow, and a new "Test" tab on the Full Page extension point — backed by a single new pure-TypeScript library: a local port of the Content SDK `RedirectsProxy` match algorithm.

The integration is intentionally additive:

- **Zero new SDK surfaces.** The simulator consumes the in-memory rules already loaded by the Manage tab (PRD-000 wiring via `lib/sdk/redirects-read.ts`). The Test surface never calls Authoring GraphQL, Preview, Publishing, or any other Marketplace SDK endpoint.
- **Zero Sitecore data-model changes.** Mode is transient UI state (ADR-0040); the stock Redirect Map template stays untouched, preserving the ADR-0023 / ADR-0008 invariants.
- **Zero new extension points.** Full Page / Context Panel / Dashboard Widget set is unchanged from PRD-000 / ADR-0011; the Test surface is a sub-route inside Full Page.
- **Single new module boundary.** `site/lib/redirects/proxy-simulator.ts` plus a fixture-driven test suite under `site/lib/redirects/__fixtures__/`. Everything else is existing-component composition.

The simulator's role in the system is **diagnostic**: it gives the operator ground truth about how the runtime proxy will resolve a URL against the rules they're authoring, before they publish. Architectural priorities, in order:

1. **Parity over cleanup** — verbatim behavioral port; quirks replicated (ADR-0038).
2. **Bounded latency** — dual time-cap (100ms per row + 3s wall-clock total) instead of Web Worker isolation (ADR-0039).
3. **Honest async** — `simulate()` returns `Promise<SimulationTrace>`; UI animates the reveal (ADR-0040).

The architecture below treats these three ADRs as binding anchors and structures the new components, data flow, and integration points around them.

## 2. System Components

This section enumerates only what is new or materially changed by PRD-004. Existing components from PRD-000 / 002 / 003 (CRUD modals, list virtuoso, publish service, picker state) carry forward without modification unless explicitly named here.

### 2.1 New library — `proxy-simulator`

**Location:** `site/lib/redirects/proxy-simulator.ts` (new file alongside the existing `redirect-type-enum.ts`).

**Responsibility:** Pure-TypeScript local port of upstream `RedirectsProxy.handle()` and its helpers. Single exported function `simulate(input): Promise<SimulationTrace>`. No SDK calls, no network, no DOM.

**Header contract (ADR-0038, FR-S6):**

```typescript
/**
 * proxy-simulator — verbatim local port of Content SDK RedirectsProxy.
 *
 * Upstream sources (captured at T2):
 *   - packages/nextjs/src/proxy/redirects-proxy.ts @ <SHA filled by T2>
 *   - packages/core/src/tools/utils.ts             @ <SHA filled by T2>
 * Retrieved: <ISO date filled by T2>
 *
 * Authority: ADR-0038 — verbatim behavioral parity; quirks replicated, not fixed.
 *   (isRegexOrUrl's `.slice(0, -1)` line is intentional and stays.)
 *
 * Known divergences from upstream:
 *   (target: empty — see M2 100% parity requirement)
 */
```

**Internal structure (matches upstream module split):**

- `simulate()` — top-level orchestrator; sets `simulationDeadline = Date.now() + 3000` (ADR-0039), iterates rules, emits trace entries.
- `isRegexOrUrl(source: string): 'regex' | 'url'` — replicates upstream `.slice(0, -1)` quirk verbatim.
- `escapeNonSpecialQuestionMarks(source: string): string` — upstream helper.
- `mergeURLSearchParams(...)` / `areURLSearchParamsEqual(...)` — upstream helpers.
- `getRedirectPatternRegex(source, flags)` — upstream pattern-to-RegExp wrapper.
- `matchFromRedirectMapRedirect(...)` / `matchRedirectItemRedirect(...)` — algorithm shape mirrors upstream.
- `runTimedTest(regex, candidate): Promise<'match' | 'no-match' | 'timeout'>` — wraps `regex.test()` in `Promise.race([test, sleep(100).then(() => 'timeout')])` (ADR-0039, FR-S4).

The module has **no runtime dependency** beyond the JavaScript standard library. NFR-6's 25KB-gz budget covers simulator + Test surface UI; the simulator itself targets <8KB gz.

### 2.2 New library — `simulator-types`

**Location:** Co-located in `site/lib/redirects/proxy-simulator.ts` (same file; exported alongside `simulate`).

**Responsibility:** Defines the `SimulationInput`, `SimulationTrace`, `SimulationStage` (discriminated-union), and `SimulationResult` types (discriminated on `matched`). See § 4 Data Model for the schema.

**Type provenance note:** these types are **locally defined to mirror upstream behavior**. There is no `@sitecore-content-sdk/*` package installed in `site/node_modules/` (the upstream is studied via the GitHub source, not consumed as a runtime dependency). The local `Mapping` type from `lib/domain/types.ts` is reused for the rules array. Rule `40-sdk-contracts.mdc` is **satisfied by absence** — no SDK surface is being called; nothing to cite from a `.d.ts`.

### 2.3 New fixture files — `__fixtures__/upstream-cases.json` + `__fixtures__/tenant-cases.json`

**Location:** `site/lib/redirects/__fixtures__/upstream-cases.json` and `tenant-cases.json` (new directory).

**Responsibility:**

- `upstream-cases.json` — input/output pairs extracted verbatim from upstream `redirects-proxy.test.ts`. **100% parity required** (M2); failing cases are bugs to fix or explicit ADR-0038 waiver entries — never silently skipped.
- `tenant-cases.json` — ≥5 cases captured from the live tenant during Tranche 1 probe; each has `description`, `redirects`, `request`, `expected`.

**Extraction strategy (architecture-level decision, see § 11 K-2):** a one-off Node script at `scripts/extract-upstream-fixtures.ts` walks the upstream test file's AST and emits `upstream-cases.json` deterministically. This makes Tranche 2 reproducible (operator can re-run the script when PRD-005 lands automated drift detection) and gives PRD-005 a structured starting point. The alternative — manual copy-paste — is rejected because (a) it does not scale to the ~30+ cases in upstream and (b) PRD-005 will need a non-manual extractor anyway.

### 2.4 New library — `site/lib/redirects/extract-upstream-fixtures.ts` (build-time, not shipped)

**Location:** `site/lib/redirects/extract-upstream-fixtures.ts` plus a runner at `site/scripts/extract-upstream-fixtures.ts`.

**Responsibility:** Read a copy of upstream `redirects-proxy.test.ts` (saved alongside as `__fixtures__/_upstream-source.ts`, gitignored), walk the AST via TypeScript's compiler API (already a project devDependency), and emit `__fixtures__/upstream-cases.json`. Outputs a manifest with extraction timestamp + count + upstream SHA. Run via `npm run extract:upstream-fixtures` (script added to `package.json`).

**Why a separate script and not inline test bootstrap:** keeps test runtime cheap; commits the extracted JSON to git so CI does not need network access; gives PRD-005 a stable scriptable target to evolve.

### 2.5 New hook — `useStaggeredRender`

**Location:** `site/hooks/use-staggered-render.ts` (new file, sibling to existing `use-count-up.ts` and `use-letter-reveal.ts`).

**Responsibility:** Given `(trace: SimulationTrace | null, options: { intervalMs?: number })`, yields the prefix of `stages` to render at each tick — `[]` initially, then `[stages[0]]`, `[stages[0], stages[1]]`, ... every `intervalMs` (default 40ms).

**Reduced-motion contract:** when `window.matchMedia('(prefers-reduced-motion: reduce)').matches`, the hook short-circuits to immediately yield the full `stages` array (instant render). FR-B5 + NFR-4 compliance.

**Cleanup contract:** on `trace` change (new test run), the hook cancels its in-flight stagger and restarts. On unmount, all timers cleared.

This is the **third** custom render-pacing hook in the codebase (count-up, letter-reveal, now staggered-render); they share a pattern but do not yet share a base abstraction. Not extracting one in this PRD — premature abstraction risk; revisit if a fourth pacing hook arrives.

## 4. Data Model

### 4.1 Sitecore data model — unchanged

PRD-004 makes **no** changes to the Sitecore data model. The Redirect Map template remains untouched (ADR-0023 / ADR-0008 invariants preserved). No new fields, no encoding-sentinel hacks (ADR-0040 considered and rejected this).

### 4.2 In-memory types (new)

Defined in `site/lib/redirects/proxy-simulator.ts`. Local definitions; no upstream `.d.ts` to cite (see § 2.2 type-provenance note).

```typescript
// Input to the simulator. Reuses the existing Mapping type from lib/domain/types.ts.

interface SimulationInput {
  url: string;            // absolute URL or path+query
  locale: string;         // ISO locale, e.g. 'en' or 'de-DE'
  rules: SimulationRule[]; // flattened across all maps; carries map ownership
  siteLanguage: string;   // for $siteLang substitution
}

// Each rule carries its parent-map context so the result can deep-link back.

interface SimulationRule {
  mapId: string;          // Sitecore item GUID of the parent Redirect Map
  rowIndex: number;       // index of this mapping within map.mappings
  source: string;         // mapping.source
  target: string;         // mapping.target
  redirectType: RedirectType;          // from the parent map (Sitecore-side; SHARED)
  preserveQueryString: boolean;        // parent map flag (SHARED)
  preserveLanguage: boolean;           // parent map flag (SHARED)
  includeVirtualFolder: boolean;       // parent map flag (SHARED)
}

// Output of the simulator.

interface SimulationTrace {
  input: SimulationInput;
  stages: SimulationStage[];           // ordered pipeline stages
  result: SimulationResult;
  startedAt: number;                   // Date.now() at simulate() entry
  durationMs: number;                  // wall-clock to resolve
}

// Discriminated union — one entry per kind of pipeline stage.

type SimulationStage =
  | { kind: 'pre-filter'; check: 'has-dot' | 'preview-mode' | 'prefetch';
      result: 'runtime-would-skip' | 'runtime-would-continue';
      note: string }
  | { kind: 'normalize'; input: string; output: string }
  | { kind: 'candidates'; locale: string; candidates: string[] }
  | { kind: 'evaluate-row';
      rule: SimulationRule;
      detectedMode: 'url' | 'regex';
      outcome: 'match' | 'no-match' | 'skipped' | 'timeout';
      capturedGroups?: string[];
      candidateThatMatched?: string;
      note?: string }
  | { kind: 'substitute'; template: string; resolved: string;
      substitutions: Record<string, string> }   // e.g. { $1: 'foo', $siteLang: 'en' }
  | { kind: 'flag-effects';
      flags: { preserveQueryString: boolean;
               preserveLanguage: boolean;
               includeVirtualFolder: boolean };
      transformedUrl: string }
  | { kind: 'dispatch';
      redirectType: RedirectType;
      finalUrl: string }
  | { kind: 'diagnostic-incomplete';
      evaluatedRows: number;
      totalRows: number;
      reason: 'wall-clock-cap' };

type SimulationResult =
  | { matched: true;
      rule: SimulationRule;          // includes mapId + rowIndex for deep-link
      finalUrl: string;
      redirectType: RedirectType }
  | { matched: false;
      candidatesTried: string[];
      rowsConsidered: SimulationRule[];     // capped to first 20 by UI; full count in next field
      rowsConsideredTotal: number;
      diagnosticIncomplete?: { evaluatedRows: number;
                                totalRows: number;
                                reason: 'wall-clock-cap' } };
```

**Design notes:**

- `SimulationRule` flattens the `(map, rowIndex)` pair so the simulator's inner loop doesn't need to iterate maps-then-rows. FullPage builds this flat list once per simulation from its in-memory `maps` array.
- `SimulationStage` is a discriminated union (not a base interface + subtypes) so the UI's switch-render in `TraceCard.tsx` is exhaustive-checked by TypeScript.
- `SimulationResult` is **separate** from `SimulationStage` because the result is the operator's primary takeaway — kept distinct so `ResultCard` can be visually dominant without dressing-up a regular stage card.
- `startedAt` + `durationMs` enable NFR-1 measurement (≤200ms p95 for ≤100 rules) without external instrumentation; the Copy-as-JSON output includes these for sharing.

### 4.3 UI state model

**Mode (per row, edit affordance):** transient component state in `RowEditForm`. Defaults to `'pattern'` on every form mount. Never persisted. (ADR-0040 / FR-A2.)

**Active tab (per FullPage):** transient component state. Defaults to `'manage'` on every page load. No URL state, no localStorage. PRD § 9 state model is explicit.

**Test inputs (per TestSurface):** transient component state — URL string, locale string. Cleared on FullPage unmount; persists across Manage↔Test tab toggles (TestSurface stays mounted but hidden via CSS / conditional render with key-stable identity).

**Last trace (lifted to FullPage):** `lastTrace: SimulationTrace | null`. Persists across Manage↔Test toggles within one page lifecycle so the operator can switch to Manage to fix a rule and switch back to see the previous trace next to their new test. Cleared on page reload.

**Decision:** lift trace state to `FullPage` (not local to `TestSurface`) **specifically because** the Test→Manage deep-link flow conditionally unmounts `TestSurface`. If trace lived in `TestSurface`, deep-linking would clobber it. Lifting to `FullPage` keeps it stable. This is the cleanest answer to the "where does this state lift" question raised in the run instructions.

### 4.4 Deep-link flow (Test → Manage → row edit)

Sequence when the operator clicks the source-row reference in `ResultCard`:

```
ResultCard.onRowClick(rule: SimulationRule)
  └─► props.onRequestEditRow(rule.mapId, rule.rowIndex)
        └─► (in FullPage) handleRequestEditRow(mapId, rowIndex)
              ├─► setActiveTab('manage')
              ├─► const map = maps.find(m => m.id === mapId)
              ├─► setSelectedMap(map)
              └─► detailRef.current?.startEditRow(rowIndex)
                   (via forwardRef imperative handle on RedirectMapDetail)
```

**No event bus, no pubsub, no context provider.** Plain prop-drilled callback + forwardRef imperative handle. Justification: only one consumer pair (TestSurface → FullPage → RedirectMapDetail), and the existing FullPage already orchestrates similar cross-component flows (write success → list refresh) by props.

**Failure modes documented:**

- Map was deleted between simulate() and click — `maps.find(...)` returns undefined; toast: "this map no longer exists; refresh"; tab still switches.
- Row was deleted between simulate() and click (different row count now) — `startEditRow(rowIndex)` either targets the wrong row or returns silently if index out of bounds. Mitigation: `RedirectMapDetail.startEditRow` validates index against current `map.mappings.length`; if invalid, toasts "this rule has been edited; please find it manually" and does not open any editor.

## 8. Security Considerations

PRD-004's attack surface is narrow because the feature is read-only with respect to the tenant and pure local compute otherwise. The risks worth naming:

### 8.1 Operator-authored regex as a local-DoS vector

A pathological regex (e.g. `(a+)+$`) is operator-authored input that runs in the operator's own browser tab. There is no cross-operator or cross-tenant exposure (each operator's tab is isolated). The risk is:

- The operator hangs their own tab.
- The operator copies a pathological pattern from a tutorial / shared bookmark and the same tab hang affects them when they test it.

**Mitigation:** ADR-0039's dual cap (100ms per row + 3s wall-clock). The cap is loud (UI surfaces "pattern too slow") so the operator knows what happened. No cross-operator amplification path exists.

**Out of scope:** sanitizing or rejecting "dangerous-looking" patterns. False positives would constrain legitimate authoring; the time-cap is sufficient.

### 8.2 Copy-as-JSON exfiltration shape

The trace JSON includes the full rule list considered (capped at 20 + count for display, but the JSON object carries `rowsConsideredTotal`). The trace is **already information the operator has access to** (they authored or imported the rules). There is no privilege boundary crossed.

**No PII** — rules contain URL patterns and target URLs, no operator identifiers, no tokens. The JSON is safe to share for debugging.

### 8.3 Deep-link path-traversal

The Test→Manage deep-link uses `rule.mapId` (Sitecore item GUID) as the lookup key, not a string path or URL fragment. GUIDs are not user-controlled in the deep-link path; they come from the simulator's own output, which got them from the loaded maps. No path-traversal or injection vector.

### 8.4 Carry-forward auth posture

The Test surface inherits PRD-000 / PRD-002's iframe + Marketplace SDK auth posture — operator is already authenticated via the parent Cloud Portal session; PRD-004 introduces no new auth requirement and no new token surface (PRD-003's server-side OAuth proxy is for publishing only and is untouched).

## 9. Risks & Tradeoffs

Aligned with PRD § 13; the architectural angle on each is below.

### R1 — Existing CRUD pipeline strips regex special chars on save/read

**Architectural angle:** this is a **data-pipeline correctness risk** at the existing `lib/url-mapping/parse.ts` ↔ `serialize.ts` boundary. The ADR-0008 encoding contract specifies URL-encoded `=`/`&`-pair encoding, which **should** preserve regex meta-chars (`^`, `$`, `(`, `)`, `?`, `\`, etc.) because they survive `encodeURIComponent` round-trip. T1 is the probe that verifies this empirically.

**If T1 fails:** the failure is in either the encoder or decoder, and the fix is a T0 patch to whichever side strips chars before T2 (simulator port) starts. Architecturally this is a small surgical fix — the encode/decode functions are short and pure — not a re-architecture.

**Why this matters more than usual:** the simulator's behavior depends on the *exact* source pattern reaching the runtime. If `^/blog/.*$` round-trips to `/blog/.*` in storage, every regex authored in v0 would silently misbehave at runtime. T1 is the architecture's existential gate.

### R2 — Simulator behavior drifts from upstream proxy after a Content SDK release

**Architectural angle:** this is a **continuous-integration risk on an external dependency we deliberately do not link**. We're shipping a verbatim port, not consuming a package, so npm version pinning offers no help. The cost of being a verbatim port is that drift is silent until someone re-checks.

**Mitigation now:** ADR-0038 + header-comment SHA capture at T2. Drift is detectable but only by manual inspection.

**Mitigation later:** PRD-005 (drift detection + AI re-sync) is the architectural answer to this risk. The `extract-upstream-fixtures.ts` script (§ 2.4) is the structured starting point — PRD-005 builds on it.

**Operator-perceived consequence if drift goes undetected:** the Test surface gradually loses fidelity; "the test said fire, the tenant didn't" reports appear. The 100% upstream-fixture parity requirement (M2) catches the *behavior* changes (the upstream test cases evolve); SHA capture catches the *source* changes.

### R3 — Catastrophic regex pattern hangs the tester UI

**Architectural angle:** ADR-0039 is the answer; this risk is the rationale. The architectural choice that matters here is **why dual-cap and not Worker isolation** — see ADR-0039's "harder" section. The cost of the cap-based approach is 3s worst-case latency on pathological inventories; the cost of Worker isolation would be bundle bloat + iframe-Worker constraints we'd have to verify in the Marketplace SDK environment + harder debug story. Bundle and complexity won for v0; revisit at PRD-006+ if authoring patterns change.

### R4 — Operator authors regex in Pattern mode (or vice versa) and is surprised at runtime

**Architectural angle:** addressed by the inline-hint affordance (FR-A4) backed by the same `isRegexOrUrl()` implementation the simulator uses. **Architecturally important:** the hint and the simulator share the **single source of truth** for mode detection — both call into the same exported `isRegexOrUrl(source)` from `proxy-simulator.ts`. If we ever diverged (e.g. UI used a "smarter" detector for the hint), the hint and the runtime could disagree, defeating the hint's purpose.

### R5 — Test surface output is too dense / overwhelms operators

**Architectural angle:** the trace's discriminated-union shape makes per-stage UI treatment cheap — `TraceCard.tsx` switch-renders by `stage.kind`. If T6 smoke shows the trace is too dense, the UI side can collapse uninteresting stages (e.g. fold "pre-filter" cards into the normalize card) without changing the simulator's emit contract. Architecture decouples emit from render.

### R6 — `isRegexOrUrl()` upstream quirk is fixed in a future SDK release

**Architectural angle:** parity is the whole point of ADR-0038. If upstream fixes the `.slice(0, -1)` quirk, our drift detector (PRD-005) flags it, an explicit decision is made (likely: update our port to match the new upstream), and the parity fixture is regenerated.

### R7 — Bundle bloat from helper UI

**Architectural angle:** NFR-6 (≤25KB gz) is a hard budget. Architecture-level mitigations baked in: no runtime regex parser library (just `new RegExp`); snippet library is static JSON inlined into the bundle as a constant; capture-group chips render from a derived count, not a runtime regex AST library. The simulator alone should fit in <8KB gz.

### R8 — `RowEditForm` extraction introduces regressions in CRUD

**Architectural angle (new risk surfaced by the architecture, not in PRD § 13):** extracting `RowEditForm` from `RedirectMapDetail` is a non-trivial mechanical refactor. The existing `commitRowEdit` / `commitAddRow` flows have nuanced server-dedup checks that must move cleanly. Architectural mitigation: the extraction is **mechanical and behavior-preserving** — tests for the existing edit-row and add-row flows must continue to pass before any PRD-004 affordance is added. Suggested ordering: T3 starts with extract-then-test parity, *then* adds the mode toggle and helpers; the QA enrichment should pin this ordering.

## 10. Open Questions

The PRD's OQ-1 through OQ-4 are operator-facing product questions and stay with the PRD. The architectural questions that remain open:

- **OA-1 — Should `useStaggeredRender` be factored against `use-count-up` / `use-letter-reveal`?** Decision: no, not in this PRD. Premature abstraction risk. If a fourth render-pacing hook arrives, revisit.
- **OA-2 — Should the deep-link flow use a router push (URL state) or in-memory state?** Decision: in-memory only (consistent with PRD § 9's "no URL state" decision for active-tab and trace). If operators ask for shareable test scenarios, OQ-3 in the PRD covers the future-opportunity path (URL hash fingerprint).
- **OA-3 — Where does the simulator yield to the event loop between rows for main-thread responsiveness?** ADR-0039's "harder" note flags `await new Promise(r => setTimeout(r, 0))` or `requestIdleCallback`. **Default decision:** yield via `setTimeout(0)` every 25 rows (cheap, deterministic, testable). The Lead Developer can adjust during T2 if profiling shows otherwise.
- **OA-4 — Should the locale dropdown's "Other..." free-text option short-circuit any normalization?** **Default decision:** the free-text value is passed verbatim to `simulate(input.locale = freeText)`; the simulator's existing locale-stripping logic handles it. If invalid, the simulator's candidate generation produces empty paths and the trace shows "no candidates" — operator can diagnose.

These are minor refinements rather than blocking unknowns; downstream stages can resolve them inline without re-opening the architecture.
