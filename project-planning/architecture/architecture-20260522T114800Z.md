> **Feature-scoped delta.** PRD-005 builds on top of PRD-000..004. Mode A scaffold (ADR-0002 / 0035 carve-out for publishing), Authoring GraphQL data path (ADR-0003), Cloud Portal iframe lifecycle, simulator port discipline (ADR-0038), regex safety (ADR-0039), promise-returning simulator (ADR-0040), lifted Test-surface state (ADR-0041), AST extractor (ADR-0042), `EditRowModal` (ADR-0043) — all carry over unchanged. ## 1. Architecture Overview

PRD-005 adds **one external read-only HTTP integration** (GitHub REST API, unauthenticated) and **one dev-time tool** (a Claude Code slash command in the product repo). It introduces zero new Sitecore SDK surfaces, zero server routes, and zero CSP changes (per ADR-0048).

The feature splits cleanly into two layers that share one piece of state:

1. **Runtime (deployed app, Mode A iframe).** A `useUpstreamDrift()` hook reads a build-time-bundled snapshot JSON, calls the GitHub commits API on demand, compares SHAs, and exposes a five-state machine. A presentational `UpstreamDriftBanner` renders on the Test tab when the hook reports `'drifted'` and the user hasn't dismissed it this session. A "Check upstream" button in the existing `TestSurface` left rail triggers `recheck()`.

2. **Dev-time (engineer workstation, Claude Code).** A new `.claude/commands/sync-redirect-proxy.md` file in the product repo (the first such file — `.claude/` does not yet exist locally) defines a procedural flow that Claude Code executes: re-fetch upstream, propose verbatim re-port via the Edit tool, regenerate fixtures via the existing AST extractor (ADR-0042), run the simulator test suite, and on green auto-bump the snapshot SHAs.

**Shared state**: a new committed file `site/lib/redirects/__fixtures__/upstream-snapshot.json` that replaces the SHA-in-header-comment approach from PRD-004. Both layers read this file; only the slash command writes it. ADR-0044 (**amended 2026-05-22**) codifies the JSON-as-data move; tracked branch for v0 is **`dev`** (operator picked option (b) at the OQ-A1 gate after the architecture-time `main` probe returned 404). Promote to `main` via a single-line snapshot-JSON edit once Sitecore publishes a `main` branch with the watched files.

**Resolved: OQ-A1 / `main` 404 finding.** Live probe of `Sitecore/content-sdk` at architecture authoring showed the repository's **default branch is `dev`, not `main`**, and `GET /repos/Sitecore/content-sdk/commits?path=packages/nextjs/src/proxy/redirects-proxy.ts&sha=main&per_page=1` returned **HTTP 404**. Operator resolution at the architecture gate: **track `dev` for v0 (option b)**. T1 captures `dev` SHAs as the baseline; everything else in this architecture stays as-written.

## 4. Data Model

No Sitecore data-model changes. No GraphQL operations. No tenant-side writes. The only new persistent shape is one local JSON file.

### `upstream-snapshot.json` schema (v1)

```typescript
type UpstreamSnapshot = {
  schemaVersion: 1;                                // enforced; mismatch → banner error
  repository: 'Sitecore/content-sdk';
  branch: 'dev' | 'main';                          // tracked branch — v0 is 'dev' per ADR-0044 amendment 2026-05-22; widen runtime literal to 'main' when Sitecore publishes
  originalPort: {                                  // audit-only; set ONCE at T1, never mutated by slash command
    branch: 'dev';                                 // PRD-004 captured 'dev'
    ports: Array<{
      path: string;
      sha: string;                                 // e.g. '30b0db8fe768...' (preserved verbatim)
      portedAt: string;                            // ISO-8601
    }>;
  };
  watchedFiles: WatchedFile[];                     // current baseline — slash command rewrites this
  knownDivergences: KnownDivergence[];             // escape hatch per ADR-0047
};

type WatchedFile = {
  path: string;                                    // 'packages/nextjs/src/proxy/redirects-proxy.ts'
  sha: string;                                     // commit SHA at baseline
  retrievedAt: string;                             // ISO-8601 of last slash-command bump
  fileHash: string;                                // SHA-256 of file content at retrieval (audit; not used by in-app detector)
};

type KnownDivergence = {
  at: string;                                      // ISO when added
  reason: string;                                  // human rationale
  function: string;                                // e.g. 'isRegexOrUrl' — name from simulator
  upstreamSha: string;                             // SHA at which divergence was logged
};
```

**Migration constraint (PRD-005 specific).** `originalPort` is set ONCE during T1 with the PRD-004 `dev` SHAs (`30b0db8fe768b83f03fd6b9772b0d3e14711c6b2` and `e6153e5e80c2076704cad0876eec3b85ec3a1a9f`, both `portedAt: 2026-05-20T18:32:24Z` per the simulator header comment). The slash command's update step **MUST NOT** read, modify, or clear `originalPort` — it touches only `watchedFiles[].sha / retrievedAt / fileHash`. The audit constant is the durable record of where the verbatim port (ADR-0038) began.

### Hook return shape

```typescript
type DriftState = 'idle' | 'checking' | 'in-sync' | 'drifted' | 'error';
type DriftError = 'rate-limit' | 'not-found' | 'network' | 'schema-mismatch' | 'unknown';

type UseUpstreamDriftReturn = {
  state: DriftState;
  lastChecked: string | null;
  errorReason: DriftError | null;
  retryAfterSeconds: number | null;                // populated on rate-limit only
  recheck: () => Promise<void>;                    // no-op if state === 'checking'
};
```

**State machine.**

```
                ┌────────┐
                │  idle  │ ◄─── initial mount (no auto-fetch — FR-C4)
                └────┬───┘
                     │ recheck()
                     ▼
                ┌──────────┐
            ┌──►│ checking │ ◄── concurrent recheck() returns early (FR-C5)
            │   └────┬─────┘
            │        │ all fetches resolve
            │        ├──── all SHAs match snapshot ────► ┌──────────┐
            │        │                                   │ in-sync  │
            │        │                                   └────┬─────┘
            │        │                                        │ recheck()
            │        └─── any SHA differs ──────────────────► ┌──────────┐
            │        │                                        │ drifted  │
            │        │                                        └────┬─────┘
            │        │                                             │ recheck()
            │        └─── any fetch failed ──────────────────────► ┌──────────┐
            │                                                      │  error   │
            │                                                      └────┬─────┘
            └─────────────────────── recheck() ─────────────────────────┘
```

`lastChecked` is written on every transition into a terminal state (in-sync / drifted / error). `error` populates `errorReason`; `retryAfterSeconds` is non-null only when `errorReason === 'rate-limit'`. `schema-mismatch` is the synthetic error when `snapshot.schemaVersion !== 1`.

## 5. API Design

### 5a. GitHub Commits API — the one external integration

**Endpoint.** `GET https://api.github.com/repos/Sitecore/content-sdk/commits?path=<path>&sha=<branch>&per_page=1`

**Headers (always sent).**
- `Accept: application/vnd.github+json`
- `X-GitHub-Api-Version: 2022-11-28`
- **No** `Authorization` header (unauthenticated; 60 req/hr/IP per ADR-0046)

**Response unwrap level — PLAIN JSON ARRAY, NO ENVELOPE.** The response body is a top-level array (`response[0].sha`). No `data` wrapper, no `result` wrapper. This is unlike every Marketplace SDK call documented in `marketplace-sdk-client` § 8b (which is single- or double-`.data` depending on map). The client module must do `const sha = (await res.json())[0]?.sha;` directly.

**Captured live response** (from architecture-time probe — `dev` branch, since the watched file did not resolve on `main`; see § 1 critical finding):

### 5b. `github-client.ts` module surface

```typescript
// site/lib/upstream-drift/github-client.ts
export type GitHubCommitResult =
  | { ok: true; sha: string; retrievedAt: string }
  | { ok: false; reason: 'rate-limit'; retryAfterSeconds: number }
  | { ok: false; reason: 'not-found' }
  | { ok: false; reason: 'network' }
  | { ok: false; reason: 'unknown' };

export async function getLatestCommitSha(
  filePath: string,
  branch: string,
): Promise<GitHubCommitResult>;
```

**Reason mapping** (FR-B3, refined with live capture):

| Observation | Reason |
|---|---|
| HTTP 200 + non-empty array | `ok: true, sha: body[0].sha, retrievedAt: new Date().toISOString()` |
| HTTP 200 + empty array (`[]`) | `'not-found'` (file existed in repo history but not on this branch / not at this path) |
| HTTP 403 + body contains `"rate limit"` (case-insensitive) | `'rate-limit'`, `retryAfterSeconds: max(0, parseInt(X-RateLimit-Reset) - Math.floor(Date.now()/1000))` |
| HTTP 404 | `'not-found'` (covers: repo renamed, branch removed, path removed) — see § 1 critical finding |
| `fetch` throws (`TypeError: NetworkError`) OR HTTP 5xx | `'network'` |
| Anything else (HTTP 4xx not above, malformed JSON, missing `[0].sha`) | `'unknown'` |

**Notes.**
- The module does NOT retry. Caller (hook) decides.
- `'use client'`-safe — no `'server-only'` directive. Pure async function.
- No `@octokit/types` dependency. Local types are sufficient and avoid a transitive bundle hit (NFR-1 5KB budget).

## 6. Infrastructure & Deployment

**Deploy model**: unchanged from PRD-000..004. Vercel static + serverless; the OAuth proxy from ADR-0035 is unaffected (publishing surface only).

**Build-time bundling of the snapshot.** `upstream-snapshot.json` is imported statically (`import snapshot from '../redirects/__fixtures__/upstream-snapshot.json'` via the existing `tsconfig.json` `resolveJsonModule: true` flag — verified at architecture time). Next 16's webpack/Turbopack bundles it into the client JS chunk. **Consequence (R8)**: an engineer-side SHA bump only reaches the deployed app after the next Vercel deploy. Between slash-command success and deploy completion, operators see the stale baseline — PRD-005 § 9 explicitly accepts this (no runtime fetch of the snapshot to keep the architecture simple).

**Hot-reload during dev (new R-arch from § 9).** Next 16 + Turbopack treats statically-imported JSON as a normal module — edits trigger HMR. The engineer running `/sync-redirect-proxy` against a live `npm run dev` will see the banner state flip without a manual restart, but this is observed-not-guaranteed behavior; the engineer should hard-reload the iframe in the portal if HMR appears stale.

**No new env vars, no new secrets, no new connect-src.** ADR-0048: `next.config.mjs` stays empty for PRD-005. A T5 structural assertion guards against accidental introduction (FR-F3).

**Existing `.gitignore` posture.** `site/lib/redirects/__fixtures__/.gitignore` already excludes `_upstream-source.ts` (verified — present at architecture time). The new `__fixtures__/upstream-snapshot.json` is NOT in that ignore (verbatim-commit per ADR-0044). A new product-repo-level `.claude/.gitignore` (or addition to root `.gitignore`) excludes `.claude/sync-redirect-proxy.log` per FR-G5.

## 7. Technology Stack

| Layer | Tech | Justification (delta only) |
|---|---|---|
| External HTTP | Browser `fetch` (no library) | One call, two headers, simple JSON. No Octokit dependency — saves bundle (NFR-1) and complexity. |
| JSON import | TypeScript `resolveJsonModule: true` (existing in `tsconfig.json`) | Pattern already used by PRD-004 for `__fixtures__/upstream-cases.json`; reuse. |
| Hook | React 19 (carry-over) | No new state library. `useState` + `useCallback` suffice for the 5-state machine. |
| Banner | Blok primitives + V4 Elevated tokens (ADR-0024 carry-over) | Per loaded `blok-marketplace-integration` skill: muted styling matches the "informational banner in a panel" pattern; `bg-muted` + `text-muted-foreground` honor the portal theme without fighting it. |
| `sessionStorage` | Browser API | Per FR-D4. Iframe origin sandbox: each Marketplace iframe gets its own `sessionStorage` per-origin per-tab — confirmed by Marketplace SDK iframe model in the loaded skill (§ 7 extension-point table). Works as expected; no cross-iframe leakage. |
| Slash command | Markdown + Claude Code's Read/Edit/Bash/WebFetch tools | Native Claude Code primitive. No external runner. |
| Bundle | Static import of JSON + ~180 LOC TS | Well under the NFR-1 5KB gz budget (target: ~2KB gz). |

**Explicit non-choices.**
- **No Octokit / `@octokit/rest`** — one endpoint, one call, no auth; raw `fetch` is correct.
- **No new state library** — `useState` is enough; introducing `xstate` for 5 states would exceed NFR-1.
- **No service worker / cache** — on-demand only; no need.
- **No CSP middleware** — ADR-0048 explicit non-change.

## 8. Security Considerations

| Concern | Posture |
|---|---|
| Outbound `fetch` to public internet | Unauthenticated, GET-only, no credentials, no `mode: 'no-cors'` (CORS is permissive on `api.github.com`). |
| User data leakage | None. The request URL is constant (no user input concatenated into the URL). Filenames are hardcoded in `upstream-snapshot.json`. |
| Snapshot tamper | Snapshot is committed to git; git history is the audit trail. No runtime mutation. |
| Slash command write surface | Local file system only — `proxy-simulator.ts`, `_upstream-source.ts`, `upstream-snapshot.json`, `upstream-cases.json`, `.claude/sync-redirect-proxy.log`. No network writes. No Sitecore tenant writes (NFR-8 verified). |
| CSP / `frame-ancestors` | ADR-0048: no app-level CSP introduced in PRD-005. Cloud Portal's outer-document CSP (per `marketplace-sdk-client` skill § 7) is unaffected. |
| Token / secret | None — unauthenticated GitHub API. PAT auth deferred to FO-5.2. |
| XSS via banner copy | Copy is static + interpolated `lastChecked` (ISO-8601 from snapshot or `Date.toISOString()` — both safe). No user-controlled string interpolation. |
| `sessionStorage` security | Per-iframe-origin scope; no cross-site reach. The key `rm-drift-banner-dismissed` carries a single literal `'1'`, never user input. |

## 9. Risks & Tradeoffs

PRD § 13 lists R1–R10. **Three new architecture-level risks** surfaced during this blueprint:

- **R-arch1 — Static JSON import vs dev-time hot-reload may not be reliable on edit during `npm run dev`.** Turbopack treats statically-imported JSON as a module; HMR usually picks up the edit, but the engineer running the slash command against a live dev server may need to hard-reload the portal iframe to observe the new SHA. *Mitigation:* slash-command success message includes a one-liner "If `npm run dev` is running, hard-reload the iframe; otherwise the SHA reaches prod after `npm run build` + deploy."

- **R-arch2 — `sessionStorage` lifetime inside the Cloud Portal iframe.** `sessionStorage` is per-origin per-top-level-tab. The Marketplace iframe gets its own origin sandbox (verified via the loaded `marketplace-sdk-client` skill § 7 / `blok-marketplace-integration` iframe shell pattern). Dismiss persists across in-iframe navigations within the same Cloud Portal tab and clears when the operator closes that tab. *No mitigation needed* — this is the correct behavior; the risk is misdiagnosis if a future engineer expects `localStorage` semantics. Documented in the hook + banner code as a one-line comment.

- **R-arch3 — AST extractor cannot recognize new upstream test patterns.** The extractor (`scripts/extract-upstream-fixtures.ts`) recognizes the upstream test idiom at the SHA it was written for: `createProxy({...})` + `createRequest({nextUrl: {...}})` + Sinon stubs. If upstream introduces a new test pattern (e.g. `setupRedirect()` helper, `vi.fn` replacing Sinon), the regenerated `upstream-cases.json` may be missing cases. Detection: the slash command's "case count printed" step (AC-3.6) — engineer compares against last-known count. *Mitigation in PRD-005:* none; engineer review at AC-3.6 catches it. *Long-term:* FO-5.6 (semantic AST diff) or extractor versioning. Document but don't solve here.

**Existing PRD risks that the architecture touches.** R1 (T1 spike — re-port size) is realized by the § 1 critical finding: file does not exist on `main`. R4 (CSP regression) is guarded by the T5 structural assertion (per FR-F3). R7 (branch rename) is exactly the § 1 finding's failure shape and the recovery path is already specified.

**Tradeoffs explicitly accepted.**

1. **Build-time JSON bundling vs runtime fetch of the snapshot.** Build-time chosen (R8). Cost: one deploy cycle lag. Benefit: zero new server route, zero CSP discussion, zero ops surface.
2. **Sequential vs parallel fetches per recheck.** Sequential (FR-C3). Cost: ~2x latency (~600ms vs ~300ms typical). Benefit: rate-limit-friendlier; simpler error attribution; M1 ≤2s budget still comfortable for 2 files.
3. **Banner state lives in hook; banner component is pure.** Hook owns; component reads via props from `TestSurface`. Cost: TestSurface holds one more piece of derived state. Benefit: easier to unit-test (hook tests RED in isolation; banner snapshot-tests with state injected via props) and aligns with ADR-0041's lifted-state pattern.

### OQ-6 resolution (extractor refetch contract)

Read of `site/scripts/extract-upstream-fixtures.ts` confirms the extractor's contract precisely:

- **Input file** (line 43): `site/lib/redirects/__fixtures__/_upstream-source.ts` — gitignored.
- **Source of input** (lines 14–17 + 332–337): the extractor does **NOT** refetch from upstream. If `_upstream-source.ts` is missing, it prints an explicit `curl` command for the operator (or another agent) to run and exits with code 1.
- **Implication for the slash command (FR-G3 / AC-3.3 / AC-3.4):** the slash command MUST, before `npm run extract:upstream-fixtures`, write the freshly-fetched upstream raw content (from `raw.githubusercontent.com/Sitecore/content-sdk/<branch>/packages/nextjs/src/proxy/redirects-proxy.test.ts`) into `site/lib/redirects/__fixtures__/_upstream-source.ts` (overwriting). The extractor reads from this file synchronously; no API calls from the extractor itself.
- **Watched file vs extractor input mismatch.** PRD-005 watches `redirects-proxy.ts` and `utils.ts`. The extractor reads `redirects-proxy.test.ts` (the test file). The slash command therefore fetches THREE upstream files per run: two for the simulator (the watched `.ts` files) + one for the extractor input (`redirects-proxy.test.ts`). All three fetches go to `raw.githubusercontent.com`; total: 3 raw + 2 commits API = 5 outbound calls per slash-command run. Comfortably within the 60/hr/IP unauthenticated budget.
- **Extractor's hardcoded `UPSTREAM_SHA` constant (line 45).** The extractor currently hardcodes `30b0db8fe768b83f03fd6b9772b0d3e14711c6b2` and stamps it into the output JSON. **PRD-005 must update this constant** at slash-command accept time — either inline-edit the file or refactor to read from `upstream-snapshot.json`.
