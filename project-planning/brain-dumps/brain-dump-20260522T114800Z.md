## 1. Idea Summary

Tell operators when the local simulator (PRD-004's `proxy-simulator.ts`) has drifted from the upstream Content SDK `RedirectsProxy` it is a verbatim port of, and give engineers a low-friction way to re-sync it. Two co-shipping pieces, layered:

1. **In-app passive detector** — a Test-tab banner that surfaces when upstream Sitecore/content-sdk `main` has a different SHA than the baseline we ported from. Detection is **on-demand only** (operator clicks "Check upstream"); SHA-mismatch only (no content-level diff in the app); banner is dismissable per session.
2. **Dev-time slash command** — a Claude Code slash command inside the product repo (`.claude/commands/`) that fetches latest upstream, reads the current simulator, proposes a verbatim re-port patch via Claude Code's edit flow, and on accept auto-bumps the SHA in the snapshot JSON file. The slash command does NOT live inside the deployed Marketplace app — it's a maintenance tool for the repo at dev time.

Net effect: PRD-004 closed the loop *at port time*; PRD-005 closes the loop *over time*, without coupling the runtime app to an LLM dependency.

## 2. Problem Statement

PRD-004 ships a verbatim local port of upstream `packages/nextjs/src/proxy/redirects-proxy.ts` + `packages/core/src/tools/utils.ts`. The simulator is **100% fixture-parity at port time** (M2), with the baseline SHA recorded in the simulator file's header comment. But upstream is a living codebase — within weeks or months, the actual `RedirectsProxy` in production-deployed tenants will likely have moved, and our simulator's trace will silently diverge.

Today there is no signal. An operator running the Test tab will see a "matched / no match" trace that looks authoritative — and may be subtly wrong because a quirk of `isRegexOrUrl` changed, a new pre-filter was added, or a flag-effect was reworked. The simulator was sold as ground truth; without drift detection, that promise has a half-life.

The cost of re-porting manually is real: tracking the upstream repo, recognizing a relevant commit, reading the diff, mapping it back to our simulator, regenerating fixtures, running tests. The slash command exists to compress that loop to "click accept on the proposed patch".

## 3. Target Users

Two distinct user types, deliberately separated:

- **Operators using the Test tab** — see the banner; do not run the slash command. Their job is "know that the simulator may be stale before I rely on its trace". They click "Check upstream", they read the banner, they tell their engineer.
- **Engineers maintaining the Redirect Manager codebase** — run the slash command at dev time when an operator or scheduled check has flagged drift. Their job is "re-port the changed function(s) verbatim, regenerate fixtures, run tests, commit".

This split matters because it keeps the deployed Marketplace app simple (one GitHub API call, one banner, no LLM dependency, no API keys, no token cost) and concentrates the AI complexity in the dev-time tool where it belongs.

## 4. Proposed Solution

**Foundational refactor (T0 in any PRD-005 release plan):**

- Migrate the baseline SHA + retrieval metadata out of `proxy-simulator.ts`'s header comment into a dedicated JSON snapshot at `site/lib/redirects/__fixtures__/upstream-snapshot.json`. Shape: `{ schemaVersion, branch, watchedFiles: [{ path, sha, retrievedAt, fileHash }], knownDivergences: [] }`. The simulator header continues to reference the JSON for human readers, but the JSON is the source of truth for the detector + slash command.
- **Re-snapshot from `main`** (not `dev` as PRD-004 captured). PRD-004's source_inputs and `proxy-simulator.ts` header point at `dev` branch SHAs (`30b0db8f…` / `e6153e5e…`); PRD-005 switches the tracked branch to `main` because `main` is what real tenants run, not the in-progress branch. If `main` differs from `dev` at the ported points, PRD-005's T1 is a one-shot re-port to land us on a stable baseline before the watcher starts.

**A — In-app passive detector (Test tab banner)**

- New component (lives in the Test tab's sticky left rail or above the trace area) — exact placement is a UI-design call. Renders only when drift is detected AND the session-dismiss flag is unset.
- "Check upstream" button → fires a single GET to the GitHub API (`GET /repos/Sitecore/content-sdk/commits?path=<watched-file>&sha=main&per_page=1`) for each of the two watched files. Compares the returned SHA against `upstream-snapshot.json`. Unauthenticated; 60/hr per IP is well under operator-on-demand traffic.
- Drift detected → banner appears with copy along the lines of: "Upstream `RedirectsProxy` has changed since this simulator was ported (last synced: <date>). Trace results may be subtly inaccurate. Ask your engineer to run `/sync-redirect-proxy` to update."
- Dismiss (X) hides the banner for the current browser session (no cross-tab persistence; reappears on next page reload).
- If the GitHub API call fails (network, rate limit, branch removed), banner shows a low-key "Couldn't reach upstream right now" + retry — does not block use of the Test tab.

**B — Dev-time slash command (`/sync-redirect-proxy`)**

- Lives in the **product repo's `.claude/commands/`** directory (`Sitecore.Plugin.EnhancedRedirectManager` repo). NOT in the parent agentic.hahn-solo orchestration repo. Operator runs Claude Code inside the product repo and types `/sync-redirect-proxy`.
- Command flow:
  1. Read `__fixtures__/upstream-snapshot.json` to get baseline SHAs.
  2. Fetch latest content from `https://raw.githubusercontent.com/Sitecore/content-sdk/main/packages/nextjs/src/proxy/redirects-proxy.ts` and the utils file.
  3. Diff vs locally-cached copy (regenerate the gitignored `_upstream-source.ts` staging file if needed).
  4. Read `proxy-simulator.ts`; identify which ported helpers / orchestrator body lines are affected by the diff.
  5. Propose a patch via Claude Code's normal edit flow — operator reviews each hunk inline.
  6. On accept: re-run `npm run extract:upstream-fixtures` to regenerate `upstream-cases.json`; run `npm test -- proxy-simulator`; report per-case pass/fail; update `upstream-snapshot.json` with new SHAs + `retrievedAt` + new `fileHash`.
  7. On fixture parity failure: leave both the simulator edit AND the snapshot un-bumped; print the failing case names; operator decides whether to (a) refine the port further, (b) add an explicit `knownDivergences[]` entry to the snapshot with rationale (ADR-0038's escape hatch).

**Notable non-decisions for v0:**

- No fully-automated PR opener; the slash command stops at "edits proposed + tests run". Operator commits + pushes manually.
- No periodic background check (no Vercel cron, no GitHub Action). On-demand only — explicit operator decision.
- No AI in the deployed app. Detection is dumb SHA comparison; resolution is the dev-time AI loop.

## 5. Value Proposition

For operators: the Test tab promise ("you can trust this trace") doesn't decay silently. The simulator either claims parity or admits drift.

For engineers: re-porting an upstream change goes from "block out 2 hours" to "click accept on a proposed patch and watch tests run". The AST extractor (ADR-0042) + fixture auto-regeneration mean the parity check is mechanical.

For the product roadmap: this is the **enabler PRD** for any future feature that relies on the simulator being correct (e.g. CI-blocking parity checks in upstream Sitecore releases, automated Marketplace app updates triggered by upstream changes, etc.). PRD-005 lands the plumbing.

## 6. Core Features

- **F1 — Snapshot JSON** at `site/lib/redirects/__fixtures__/upstream-snapshot.json` with `branch: "main"`, two `watchedFiles`, `knownDivergences[]` (initially empty).
- **F2 — One-shot re-port from `main`** as PRD-005 T1 (if `main` diverges from the `dev` SHAs PRD-004 recorded).
- **F3 — Migrate `proxy-simulator.ts` header** to reference the JSON as authoritative; keep human-readable doc text but stop using the comment as a data source.
- **F4 — GitHub API client** (`site/lib/upstream-drift/github-client.ts` or similar) — single `getLatestCommitSha(file, branch)` function, unauthenticated, with error envelope for network/rate-limit/branch-removed.
- **F5 — Drift check hook** (`use-upstream-drift.ts`) — exposes `{ state: 'idle' | 'checking' | 'in-sync' | 'drifted' | 'error', lastChecked, diffSummary, recheck() }`. On-demand only — no `useEffect` mounting fetch.
- **F6 — Drift banner component** — Test-tab-scoped; renders conditional on `state === 'drifted'` AND session-dismiss flag. Dismiss writes to `sessionStorage`.
- **F7 — "Check upstream" trigger** — button in the Test-tab rail (placement TBD by UI design); primary action; calls `recheck()`.
- **F8 — Slash command `/sync-redirect-proxy`** — Markdown file in product repo `.claude/commands/` defining the full flow (steps 1-7 of § 4 B). Self-contained.
- **F9 — Snapshot auto-bump on accept** — slash command writes new SHA + timestamp + fileHash to `upstream-snapshot.json` only after fixtures regenerate and tests pass.
- **F10 — `knownDivergences[]` escape hatch** — operator can record a deliberate non-port (e.g. "upstream added Y; we choose to not replicate for reason Z") with a structured entry; ADR-0038 already permits this. The slash command surfaces existing entries when proposing patches.

## 7. Decisions

- **D1** — In-app drift signal lives as a **banner on the Test tab** (in-context, where the simulator is actually used). [§ shape Q1]
- **D2** — In-app does **passive detection only**; AI involvement is **out of the deployed app**. Resolution path is a **dev-time slash command** in the product repo's `.claude/commands/`. [§ shape Q2]
- **D3** — Check trigger is **on-demand only** — manual click on "Check upstream" button; no automatic check on mount, no scheduled background check. [§ shape Q3 + open-Q follow-up]
- **D4** — Detection granularity is **SHA mismatch only** — single GitHub API call per watched file; cheap; banner copy must be careful to say "upstream changed, review" not "drift detected" to avoid false-positive whiplash from comment-only upstream changes. [§ shape Q4]
- **D5** — Slash command depth: **AI proposes patch via Claude Code's edit flow** + regenerates fixtures + runs tests + reports per-case pass/fail + auto-bumps snapshot SHA on accept. [§ shape Q5]
- **D6** — Snapshot baseline lives in a **dedicated JSON file** at `__fixtures__/upstream-snapshot.json`. Source of truth. Simulator header becomes documentation referencing the JSON. [§ shape Q6]
- **D7** — Banner UX is **dismissable per-session** — X-close hides until next page reload; no localStorage persistence. [§ shape Q7]
- **D8** — Watched file scope is **just the 2 ported files** (`packages/nextjs/src/proxy/redirects-proxy.ts` + `packages/core/src/tools/utils.ts`). [§ shape Q8]
- **D9** — GitHub API is **unauthenticated** in v0 (60/hr per IP is plenty for on-demand only). [§ open-Q follow-up]
- **D10** — Initial check trigger is a **manual button click**, NOT automatic on Test-tab mount. Banner can only appear after the operator has explicitly asked for a check. [§ open-Q follow-up]
- **D11** — Slash command on patch-accept **auto-updates the SHA** in `upstream-snapshot.json` (after fixtures regenerate + tests pass). Operator does not manually bump. [§ open-Q follow-up]
- **D12** — Tracked upstream branch is **`main`** (NOT `dev` as PRD-004 captured). `main` is what real tenants run; `dev` is in-progress. PRD-005 T1 includes a one-shot re-snapshot + possible re-port if `main` differs from the `dev` SHAs PRD-004 recorded. [§ open-Q follow-up]

## 8. Assumptions

- **A1** — `https://api.github.com/repos/Sitecore/content-sdk/...` and `https://raw.githubusercontent.com/Sitecore/content-sdk/main/...` will remain stable, public, unauthenticated-readable endpoints. (GitHub has not changed this contract for years.)
- **A2** — Sitecore/content-sdk will keep the two watched files at the same paths (`packages/nextjs/src/proxy/redirects-proxy.ts` + `packages/core/src/tools/utils.ts`). If a file is renamed or relocated, the snapshot config needs updating manually; the watcher will surface this as an error (e.g. 404), not as a silent pass.
- **A3** — `main` branch at Sitecore/content-sdk represents the production-deployed Content SDK that real tenants run. (May be a slight simplification — tenants may run pinned older versions — but `main` is the closest moving target to "what production looks like next".)
- **A4** — Operator running Claude Code in the product repo has a working `git` + `npm` toolchain (the slash command shells out to `npm run extract:upstream-fixtures` and `npm test`). No new prerequisite over PRD-004.
- **A5** — Patch-accept auto-bump in `upstream-snapshot.json` is acceptable from an audit-trail standpoint because the git commit is the durable record. (Operator commits the simulator edit + snapshot bump + regenerated fixtures together.)

## 9. High-Level Technical Considerations

- **Zero new deployed-app SDK surfaces.** The in-app check is a `fetch()` to `api.github.com` (CORS-friendly; no proxy needed). No `@sitecore-marketplace-sdk/xmc` call, no Authoring GraphQL, no server-side OAuth.
- **CSP frame-ancestors compatibility.** Adding a `fetch()` to `api.github.com` may require widening `connect-src` in `next.config.ts` / response headers. Verify against the existing CSP set in PRD-001/002/003.
- **Bundle delta** — well under PRD-004's NFR-6 budget; one `fetch()` + a snapshot JSON loaded as a static import. Estimate <2KB gz delta.
- **No runtime LLM dependency in the deployed app.** Decided explicitly. AI lives in the dev-time slash command only.
- **Slash command implementation** — `.claude/commands/sync-redirect-proxy.md` in the product repo. Follows the Claude Code slash command convention. Uses Read/Edit/Bash tools. Idempotent (running twice in a row when no drift exists = no-op).
- **Snapshot schema versioning** — `schemaVersion: 1` from day one so future shape changes (e.g. adding `branch` per-file, adding `lastDriftDetectedAt`) are explicit migrations.
- **One-shot re-port at T1** — if `main` SHAs differ from the `dev` SHAs PRD-004 recorded, the existing simulator may need adjustments. Likely cheap (Sitecore's `dev` and `main` are usually close); could be a no-op if `main` is currently in sync with the same commits. **Verify via spike at T1 before committing to scope.**
- **GitHub API failure modes** — 403 rate-limit, 404 (file moved/deleted), 5xx (GitHub outage), network error. All surface as banner state `'error'` with a low-key message; never block Test tab interaction.
- **Test surface** — the slash command writes to the simulator and snapshot. Tests are the parity contract — `npm test -- proxy-simulator` is the gate. The slash command running tests before SHA bump means a failed-test state leaves the simulator + snapshot consistent (no half-applied state).
- **No PR auto-creation for v0** — operator commits manually. Future: a follow-on PRD could add `gh pr create` integration to the slash command.
- **Accessibility** — banner must be `role="status"` (NOT `alert`) — drift is informational, not critical. Reuse PRD-004's hint-styling patterns from the deferred FO-14 — copy can be muted-tone, not warning-red.
- **Theme parity** — banner must render correctly in light / dark / system per global theme policy. Cheap given PRD-002 token system.

## 10. Risks

- **R1 — False-positive whiplash from upstream comment-only changes.** SHA-mismatch only means a comment fix in upstream `redirects-proxy.ts` triggers the banner. **Mitigation:** banner copy says "upstream changed, review the diff" not "drift detected"; slash command's diff view makes it obvious when the change is comment-only (operator can then bump the SHA without re-porting). Acceptable trade-off vs the cost of fingerprinting.
- **R2 — `main` and `dev` divergence at PRD-005 T1.** Switching tracked branch from `dev` to `main` may require a one-shot re-port. **Mitigation:** T1 is a spike-and-decide tranche that determines scope before T2 build begins.
- **R3 — GitHub API rate limit (60/hr per IP unauthenticated).** A team of operators on the same egress IP could hit this quickly. **Mitigation:** check is on-demand only (D3), so daily traffic per operator is small (1-2 checks/day). If hit, banner shows the rate-limit error gracefully. Long-term: PAT-based auth is a follow-on PRD.
- **R4 — CSP `connect-src` blocks `api.github.com`.** **Mitigation:** verify and widen at T1; ADR-style decision if the CSP change has unexpected side-effects.
- **R5 — Slash command's AI patch proposal is subtly wrong.** The patch looks right but breaks fixture parity. **Mitigation:** the test-run step in the slash command catches this BEFORE the SHA bump. Failed-test state is recoverable (no committed change).
- **R6 — Operator dismisses banner; later loses the dismissal across reloads and thinks it's a new drift event.** **Mitigation:** banner copy includes `lastChecked` timestamp + repeated copy is the same — operator can re-dismiss in one click. Per-session dismissal (D7) is intentionally lighter than localStorage to avoid the opposite problem (stale dismissal hiding a real new event).
- **R7 — Future Sitecore branch rename** (e.g. `main` → `master` or vice versa). **Mitigation:** snapshot JSON carries the branch name; explicit error surfaces if the branch 404s. Recovery is an operator edit of the JSON + re-snapshot.
- **R8 — Bundle delta exceeds PRD-004's NFR-6 (≤25KB gz).** **Mitigation:** measure at T-end; the implementation is so thin (one fetch, one JSON) that this is unlikely, but worth a gate.

## 11. Open Questions

- **OQ-1** — Should `__fixtures__/upstream-snapshot.json` be committed verbatim, or kept as a `.example` template + a gitignored real file (similar to `.env.example` pattern)? **Default:** committed verbatim. The SHA is not a secret; the audit trail is the value. Decide in PRD.
- **OQ-2** — Where exactly does the "Check upstream" button render in the Test tab? Above the URL input? Below the Test button? In a new "Diagnostics" expander? **Default:** UI design decision; punt to `/architect` → `/ui-design` if scope_dial includes UI variants.
- **OQ-3** — Does the slash command need to support a "force re-port even if SHAs match" mode (for testing the slash command itself, or for re-porting after a manual divergence)? **Default:** add a `--force` flag, but only when first user complains. Keep v0 simple.
- **OQ-4** — Should the snapshot JSON record a hash of the simulator file itself (so the slash command can detect "operator hand-edited the simulator since the last sync" and warn before overwriting)? **Default:** out of scope; git history is the audit trail.
- **OQ-5** — If `main` diverges from `dev` at PRD-005 T1 enough to require a substantial re-port, do we split PRD-005 into PRD-005a (re-snapshot + detector) + PRD-005b (slash command), or absorb into one PRD with a longer T1? **Default:** absorb; decide at T1 if pain emerges.
- **OQ-6** — Does the slash command need to handle the `__fixtures__/_upstream-source.ts` gitignored staging file regeneration explicitly, or does the AST extractor already cover that? **Default:** verify at `/architect`; if the extractor only reads (not refetches), the slash command needs a separate fetch step.
- **OQ-7** — Banner accessibility — should it be in the tab's tab-order before the Test button, or after? **Default:** UI design + a11y review; lean toward "after" since the banner is informational and the Test button is the primary action.
