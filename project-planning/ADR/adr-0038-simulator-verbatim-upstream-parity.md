# ADR-0038: Simulator is a verbatim port of upstream `RedirectsProxy` with 100% test-fixture parity

## Status

Accepted

## Context

PRD-004 introduces a redirect Test surface (Full Page, secondary tab) that simulates how the Content SDK `RedirectsProxy` would evaluate a given URL against the tenant's current redirect inventory. The simulator is a local TypeScript port of upstream `packages/nextjs/src/proxy/redirects-proxy.ts` + supporting helpers from `packages/core/src/tools/utils.ts`.

Two tensions sit on this decision:

1. **Parity vs. cleanup.** The upstream `isRegexOrUrl()` helper strips the last character via `input.slice(0, -1)` before its URL-shape regex test. This appears to be a bug — there is no obvious functional reason for it — but it is the runtime contract every Content SDK Marketplace tenant runs against today. If our simulator "fixes" this in a port, our trace will diverge from the actual proxy on any URL whose last character matters to the shape test (e.g. a URL ending in `_` or `.` or `?`).
2. **Drift detection vs. correctness.** PRD-005 (queued) will add upstream-source drift detection — a button that fetches latest-on-`dev` of the two source files and diffs against a snapshot. Drift detection needs a **stable baseline**. If our port diverges from upstream by design or accident, the drift detector cannot tell signal from noise.

The third pressure is operator confidence. The Test surface is the operator's only ground truth before publishing — if the simulator says "your rule fires for `/old-page`" but the live proxy says otherwise, the feature is worse than not having it.

## Decision

The simulator is a **verbatim behavioral port** of the upstream `RedirectsProxy` match algorithm, including known quirks. Variable names may differ; semantics must not.

Specifically:

1. `site/lib/redirects/proxy-simulator.ts` reproduces the algorithm of `RedirectsProxy.handle()`, `matchFromRedirectMapRedirect()`, `matchRedirectItemRedirect()`, `getRedirectPatternRegex()`, plus the helpers `isRegexOrUrl()`, `escapeNonSpecialQuestionMarks()`, `mergeURLSearchParams()`, `areURLSearchParamsEqual()`.
2. Quirks are **replicated, not fixed**. The `isRegexOrUrl()` `.slice(0, -1)` line stays. If upstream fixes it in a future release, our drift detector (PRD-005) will flag the change and an explicit decision is made then.
3. **100% parity required** against an imported fixture file `__fixtures__/upstream-cases.json`, generated by extracting input/output pairs from the upstream `redirects-proxy.test.ts`. Every fixture passes, or:
   - Fix the simulator (preferred), OR
   - Add an explicit ADR waiver entry to a per-divergence section in this ADR, with rationale + tracking issue
4. **Header comment** at the top of `proxy-simulator.ts` records: upstream source URLs (both files), the **commit SHA** retrieved during T2, the retrieval date, ADR-0038 reference, and a "Known divergences from upstream" section (target: empty).
5. **Pre-filters surfaced in trace** (URL contains `.`, preview-mode, prefetch). Runtime short-circuits on these; our simulator continues for diagnostic visibility — but the trace makes the difference explicit so operators know what runtime would have done.

## Consequences

**Easier:**
- PRD-005 drift detection has a clean baseline — any upstream change is detectable
- Operator confidence in the Test surface: matches runtime exactly
- Test fixtures from upstream become the ground truth — no "we test what we think upstream does"
- When operators report "the test said it would fire but it didn't," the root cause is almost certainly tenant data drift or a missed fixture case, not a port bug

**Harder:**
- We carry forward upstream's bugs (e.g. `isRegexOrUrl()` `.slice(0, -1)`) until upstream fixes them
- T2 work includes building the upstream-fixture extractor — non-trivial one-time effort
- Refactoring temptation grows over time; every refactor must preserve fixture parity, slowing intentional improvement
- Operator surprise possible when a simulator output is technically "weird" but matches upstream verbatim — we mitigate via trace transparency
