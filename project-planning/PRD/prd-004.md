## 1. Executive Summary

PRD-004 adds two co-shipping capabilities to the Redirect Manager Marketplace app:

1. **Regex source mode** — a new **small edit modal dialog** (`EditRowModal`) that opens when an operator clicks any row in `RedirectMapDetail`. The modal owns only the **source pattern**, **destination**, and **mode toggle** (Pattern / Regex). Map-level fields — `RedirectType`, `IncludeVirtualFolder`, `PreserveQueryString`, `PreserveLanguage` — are not in this modal (they live in the existing map-settings UI, unchanged). The modal carries regex authoring helpers (snippet library, capture-group chips, `$siteLang` chip, optional live regex tester) and save-time validity check, plus an inline hint when the operator's manual mode does not match the runtime auto-detect heuristic. **This modal replaces the existing inline-row editing in `RedirectMapDetail`** (ADR-0043) — one way to edit, no UX duality.
2. **Test surface** — a secondary tab ("Test") on the Full Page workspace with a **two-column layout**: a sticky left rail for **scope picker** (Collection → Site → Map(s)) + URL input + locale + Test button, and a scrollable right area for trace cards. The scope picker reuses existing `lib/sdk/sites.ts` helpers (`listCollections`, `listSites`) and the existing `lib/sdk/redirects-read.ts` helper for map loading — zero new SDK surfaces. The simulator evaluates only against rules from the picked maps within the picked Collection + Site (not tenant-wide). Picker state persists to localStorage per the ADR-0022 versioned-key pattern. Output is a full structured trace of how the Content SDK `RedirectsProxy` would evaluate the URL against the scoped redirect inventory — matched? which row? which mode? which capture groups? which pipeline transformations? final destination? redirect type?

Both surfaces are net-additive — zero behavioral change to the existing Manage tab, zero changes to the Sitecore Redirect Map template, zero new SDK surfaces. The simulator is a local port of the upstream `RedirectsProxy` match algorithm, kept in parity with upstream through a Tranche 1 capture probe and an SDK-test-fixture-driven test suite. PRD-005 (deferred) will add upstream-source drift detection and an AI re-sync slash command to keep the simulator current automatically.

## 2. Problem Statement

The Redirect Manager today assumes plain-URL patterns. The Content SDK proxy already supports regex (per-row, no Sitecore flag needed — `isRegexOrUrl` auto-detects from syntax), but operators have **no way to author regex confidently**:

- No mode signal in the UI — operators do not know whether a pattern is parsed as URL or regex
- No save-time validation — invalid regex (`(a+]$`) saves silently and fires only at runtime
- No way to verify a rule actually fires the way they expect against a real URL — operators must publish to the tenant and click around production to validate

Mistakes are caught after deployment, at the worst possible time. PRD-004 closes the loop with explicit authoring + an in-app dry-run that mirrors the upstream proxy's match algorithm exactly.

## 3. Goals and Success Metrics

### Goals

- **G1** — Make regex authoring a first-class flow in the Redirect Manager, on par with plain-URL authoring
- **G2** — Eliminate the "publish-and-pray" loop by letting operators verify a rule fires against a sample URL before save
- **G3** — Build a simulation foundation that PRD-005 (drift detection + AI re-sync) can build on, with explicit parity to the upstream proxy

### Success Metrics

- **M1** — Save-time validation rejects every invalid regex before it lands in Sitecore (acceptance: 100% of malformed regex inputs caught; verified via tests)
- **M2** — Simulator output matches upstream `RedirectsProxy` behavior on **100%** of imported upstream test fixtures. Any failing upstream fixture is either a bug to fix OR requires an explicit ADR waiver before merge — never silently skipped.
- **M3** — Tranche 6 real-tenant smoke: ≥80% of operator-selected URLs produce simulator output that matches the actual tenant Edge response (acceptance: operator validates 5-10 URLs). **Response policy when <80%:** PR is marked `shipped_with_caveats`; each mismatch is captured as a follow-up task with the captured trace + actual Edge response; hard-stop only when the mismatch indicates a parity-breaking bug in the simulator itself (not a tenant-data quirk). **Smoke procedure:** operator opens the tenant's published site in a fresh browser window, navigates to the test URL, observes the network response (status code + Location header), records (URL, expected, actual) in a smoke-evidence file under `project-planning/smoke/smoke-prd-004-<timestamp>.md`.
- **M4** — Test surface trace is operator-actionable: when a URL does NOT match, the trace names which candidate paths were tried and which rows were considered (acceptance: smoke walkthrough confirms operator can diagnose a non-match in <30 seconds without leaving the app)

## 4. Target Users

Same persona set as PRD-000/002/003; this PRD adds **a new authoring scenario** (regex) and **a new verification scenario** (testing) to existing user types:

- **Site administrators managing redirect inventories** — primary regex authors. Use Pattern mode for simple paths, switch to Regex mode for complex migration scenarios (e.g. moving an entire blog under a new URL structure with capture-group substitution).

## 6. User Stories

### US-R1 — Author a regex redirect rule

**As a** site administrator
**I want** to click a row in the map and have an edit modal open with a Pattern / Regex mode toggle, and switch it into Regex mode to author a pattern with capture groups
**So that** I can express migration rules that would be impossible or tedious in plain-URL mode

**Acceptance Criteria:**
- **AC-R1.1** — Clicking any row in `RedirectMapDetail` opens `EditRowModal`. Modal renders a segmented Pattern / Regex toggle full-width above the source input, defaulting to Pattern on every open. Modal contains only source + destination + mode + helpers — no `RedirectType`, no flags (those are map-level)
- **AC-R1.2** — Switching to Regex inside the modal changes the source-input affordances: snippet library appears below the source input, capture-group chips appear in the destination input
- **AC-R1.3** — When source contains `(group1)(group2)`, destination chips show `$1`, `$2`, `$siteLang` (always)
- **AC-R1.4** — Live regex tester accepts a sample URL, evaluates the pattern via `new RegExp(source).test(sampleURL)` (with `.match()` to surface capture groups), displays "match" or "no match" + each capture group's value
- **AC-R1.5** — Save fails with an inline error if `new RegExp(source, flags)` throws; error message includes the exception's `.message` text
- **AC-R1.6** — Save fails with an inline error if the destination references `$N` where N exceeds the count of capture groups in source. Specific rules:
  - `$0` is rejected (block save with "$0 is not supported; use $1+ for capture groups")
  - Gap-in-numbering is rejected (e.g. `$1` + `$3` when source has 2 groups → block save with "destination references $3 but source has only 2 capture groups")
  - `$siteLang` is **exempt** from the cross-check — it is always available regardless of group count
  - Out-of-scope edge case acknowledged: counting capture groups via `new RegExp(source).source.match(/\((?!\?)/g)` is naïve — it over-counts escaped `\(` and parens inside character classes `[(]`. v0 documents this as a known false-positive; T3 acceptance permits the operator workaround "ignore the warning, save anyway is blocked only on actual runtime parse failure" (see FR-A7)

### US-R2 — Get hinted when manual mode disagrees with runtime auto-detect

**As a** site administrator opening an existing row
**I want** an inline hint when the runtime would treat my pattern differently than my manually selected mode
**So that** I do not silently ship a rule that fires unexpectedly at runtime

**Acceptance Criteria:**
- **AC-R2.1** — When mode is Pattern but `isRegexOrUrl(source) === 'regex'`, render a non-blocking inline hint below the source input: "this pattern contains regex characters; runtime will treat it as regex — switch to Regex mode?"
- **AC-R2.2** — When mode is Regex but `isRegexOrUrl(source) === 'url'`, render a non-blocking inline hint: "this pattern looks like a plain URL; switch to Pattern mode for simpler authoring?"
- **AC-R2.3** — Hint includes a one-click "Switch mode" button that flips the toggle without losing the operator's edits
- **AC-R2.4** — Hint is purely advisory — save is never blocked because of it
- **AC-R2.5** — Hint is announced to assistive tech as a status (not an alert) — does not steal focus

### US-T0 — Scope the Test surface to a specific Collection + Site + Map(s)

**As a** site administrator with multiple sites in a tenant
**I want** the Test surface to test only against the maps relevant to the site I care about
**So that** my trace is not polluted by rules from unrelated sites and I can focus on the operational context I'm working in

**Acceptance Criteria:**
- **AC-T0.1** — Left rail (sticky) of the Test tab renders three cascading selectors: **Collection** → **Site** → **Map(s)** (multi-select for the last one). Initial state is empty (no defaults) unless localStorage has a prior selection for this `(tenantId, surface)` key, in which case the prior selection is restored.
- **AC-T0.2** — Collection picker is populated from `lib/sdk/sites.ts → listCollections(client, sitecoreContextId)`. Site picker is populated from `listSites(client, sitecoreContextId)` filtered client-side by chosen collection. Map picker is populated from `lib/sdk/redirects-read.ts` filtered to maps within the chosen site.
- **AC-T0.3** — Each picker shows a skeleton state while data loads. Loading errors surface inline with a retry button.
- **AC-T0.4** — Changing Collection clears Site + Map selections; changing Site clears Map selection. Cascading invalidation is automatic.
- **AC-T0.5** — Test button is disabled until at least one Map is selected AND the URL input is non-empty. Disabled-state tooltip explains: "Pick a collection, site, and at least one map to enable testing."
- **AC-T0.6** — Scope picker state persists to localStorage under key `rm-test-picker-v1` per ADR-0022 versioned-key pattern. Storage shape: `{ schemaVersion: 1, tenantId, collectionId, siteId, mapIds[], updatedAt }`.
- **AC-T0.7** — If the persisted Collection / Site / Map no longer exists on the current tenant (e.g. operator switched tenants or content was deleted), the picker silently resets that level and downstream levels, surfacing a brief inline message: "previous selection no longer available — pick again."

### US-T1 — Test a URL against the current redirect inventory

**As a** migration operator
**I want** to paste a legacy URL into a tester, click Test, and see whether a redirect would fire
**So that** I can verify my rules cover the migration cases before publishing

**Acceptance Criteria:**
- **AC-T1.1** — Full Page workspace renders "Manage / Test" segmented tabs below the WorkspaceHero
- **AC-T1.2** — Test tab renders a two-column layout: **left rail (~360px, sticky)** holds the scope picker (US-T0) + URL input + locale dropdown + Test button; **right area (scrollable)** holds the trace output. On viewports below 768px, columns stack vertically (scope picker collapses into a top accordion).
- **AC-T1.3** — URL input accepts both absolute (`https://example.com/path?qs=1`) and path+query (`/path?qs=1`); both produce identical simulation results
- **AC-T1.4** — Locale dropdown defaults to `en`; options are the static list `en, de-DE, fr-FR, es-ES, it-IT, nl-NL`. A final "Other..." option opens a free-text input that accepts any string matching `^[a-z]{2}(-[A-Z]{2})?$`; invalid free-text rejected inline.
- **AC-T1.5** — Test button submits the URL + locale to the simulator; the simulator returns a Promise that resolves with the full structured trace; the trace renders in the output area within 200ms p95 (for ≤100 rules inventories). Card render uses a visual stagger animation; `prefers-reduced-motion: reduce` falls back to instant render.
- **AC-T1.6** — Output for a matched URL: trace cards showing each pipeline stage with input/output values; final card highlights the destination URL + redirect type (301 / 302 / ServerTransfer) **+ source row reference**. Clicking the source-row reference closes the Test tab, switches to Manage tab, scrolls to the parent map, and opens `EditRowModal` for that row.
- **AC-T1.7** — Output for an unmatched URL: trace cards showing the candidate paths tried, a "rows considered" card (capped per AC-T2.2), and a final "no match" card.
- **AC-T1.8** — Footer "Copy as JSON" button copies the complete trace object to clipboard (browser-native `navigator.clipboard.writeText`)
- **AC-T1.9** — Pre-filter skips on the request URL appear as their own trace card before the candidate-paths card. Examples: "URL contains `.` → file-path filter would skip in runtime; simulator continues for diagnostic visibility" or "URL detected as preview/prefetch (simulator never triggers these — informational only)". This makes operator diagnosis of "why doesn't my rule fire" cover the upstream proxy's pre-filters explicitly.

### US-T2 — Diagnose why a regex rule did not fire

**As a** site administrator debugging an operator complaint
**I want** the test surface to show me which candidate paths the proxy generated and why my regex did not match
**So that** I can quickly fix the rule without trial-and-error in production

**Acceptance Criteria:**
- **AC-T2.1** — The trace's "candidate paths" card shows all paths the proxy would try (incoming raw, normalized, locale-stripped × 2; with/without query string) — clearly labeled
- **AC-T2.2** — The "rows considered" card lists rows in evaluation order with pattern, mode, and per-row match outcome ("regex tried, no match" / "url tried, no match" / "skipped: locale rule, no match" / "skipped: pre-filter excluded request" / "timeout (pattern too slow)"). **UI cap:** show the first 20 rows; if more, render "+ N more rows considered (no match)" with an expand control that reveals the remainder in chunks of 50. **Computational cap:** simulation is wall-clock-bounded — total evaluation across all rows is capped at 3 seconds; if reached, simulator stops evaluating and emits a final "diagnostic incomplete after 3s — evaluated X of Y rows" trace card. This bounds worst-case wait on pathological inventories (500+ rows × catastrophic regex).
- **AC-T2.3** — When a regex hangs (>100ms per row), the row is marked "pattern too slow — runtime would also stall here" in the trace; simulator does not block the UI; the 3s wall-clock cap in AC-T2.2 still applies.

### US-T3 — Verify simulator matches upstream proxy

**As a** developer extending the Redirect Manager
**I want** the simulator's behavior to be guaranteed-equivalent to the upstream `RedirectsProxy` via test fixtures
**So that** I can rely on simulator output as authoritative when operators report runtime mismatches

**Acceptance Criteria:**
- **AC-T3.1** — `site/lib/redirects/proxy-simulator.test.ts` imports input/output pairs from the upstream `redirects-proxy.test.ts` (committed as a static JSON fixture file under `site/lib/redirects/__fixtures__/upstream-cases.json`)
- **AC-T3.2** — `site/lib/redirects/__fixtures__/tenant-cases.json` contains ≥5 cases captured during Tranche 1 probe — each is a real redirect from the live tenant with expected outcome
- **AC-T3.3** — Both fixture sets run as parameterized test cases; all upstream-case tests pass before T3 can be marked complete; any known divergence is documented in code header + ADR-0038
- **AC-T3.4** — Header comment of `proxy-simulator.ts` records the upstream commit SHA + retrieval date for both source files (`redirects-proxy.ts` + `utils.ts`)

## 7. Functional Requirements

### A — `EditRowModal` (replaces inline editing per ADR-0043)

- **FR-A0** — `EditRowModal` is a new `@blok/dialog` (or equivalent Blok primitive) opened by clicking any row in `RedirectMapDetail`. Modal is dismissable via close button, Esc, or click-outside (with unsaved-changes confirmation when source/destination differ from original).
- **FR-A1** — `EditRowModal` exposes a segmented control with two options labeled "Pattern" and "Regex" full-width above the source input; default selection is "Pattern" on every modal open
- **FR-A2** — Mode is **transient state** — not persisted to Sitecore. On every modal open (clicking a row to edit, or navigating to a different row), the toggle starts at "Pattern" regardless of pattern content. (ADR-0040.)
- **FR-A8** — Modal contains ONLY: mode toggle, source input, inline hint slot, snippet library (Regex mode only), sample-URL tester (Regex mode only, MVP-deferable), destination input, capture-group chip strip (Regex mode + groups > 0), Save / Cancel footer. **Map-level fields (RedirectType, IncludeVirtualFolder, PreserveQueryString, PreserveLanguage) are NOT in this modal** — they live in the existing map-settings UI and are managed at map granularity.
- **FR-A9** — Save action commits the row's source + destination back to the parent map's `UrlMapping` field via existing `lib/sdk/redirects-write.ts` (no new SDK calls). Cancel action discards edits.
- **FR-A3** — On mode change, the input affordances re-render: Regex mode shows the snippet library + sample-URL tester + capture-group chips in destination; Pattern mode hides those affordances
- **FR-A4** — When the source pattern matches the inverse of `isRegexOrUrl()` for the selected mode, render the inline hint (US-R2)
- **FR-A5** — Save-time validation per AC-R1.5 / AC-R1.6 (regex parse + capture-group reference check)
- **FR-A6** — Snippet library renders 5-6 patterns; clicking a snippet inserts its source at the cursor position in the source input (or replaces selected text)
- **FR-A7** — Capture-group chips: parse the current source via `new RegExp(source).source.match(/\((?!\?)/g)` (non-capturing-group-aware) to count groups; render `$1` through `$N` chips + always `$siteLang`; clicking a chip inserts at destination cursor.
  - **v0 known limitation:** this paren-counting regex over-counts escaped literal parens (`\(`) and parens inside character classes (`[(]`). Operators authoring patterns like `^/contact\(us\)$` will see a phantom group count and may see save-time validation flag a non-existent group reference. **Workaround:** the regex-parse step (AC-R1.5) is authoritative — if `new RegExp(source, flags)` succeeds, the pattern is valid; the count-based cross-check (AC-R1.6) is advisory in these edge cases. Document in the inline error message: "if you believe this is a false positive, the pattern is still valid; the count check has known edge cases for escaped or character-class parens."
  - **Out-of-scope for v0:** robust group-counting via AST or runtime exec — defer until operators complain.

### B — Test surface (two-column layout with scope picker)

- **FR-B2** — Test tab renders a two-column layout. **Left rail (sticky, ~360px wide):** Scope picker (Collection → Site → Map(s) per US-T0), followed by URL input (text), locale dropdown (default `en`), Test button (primary, disabled until scope and URL are both valid). **Right area (scrollable):** trace output cards. Below 768px the columns stack vertically with the scope picker as a top accordion.
- **FR-B3** — URL parsing: if input starts with `http://` or `https://`, parse as absolute URL via `new URL(input)`; otherwise treat as path+query (must start with `/`)
- **FR-B4** — Invalid input shows an inline validation message; Test button stays disabled until valid AND scope picker has at least one selected map
- **FR-B5** — Test button submits to the simulator (Promise-returning); while pending, the Test button shows a loading spinner; on resolve, the full trace renders in the output area with a visual stagger animation (one card per ~40ms); `prefers-reduced-motion: reduce` falls back to instant render of all cards at once. **Not progressive streaming** — the simulator computes the full trace then UI animates the reveal.
- **FR-B6** — Trace cards: one per stage of the simulator pipeline; each card shows: stage name, inputs, outputs, transformation applied
- **FR-B7** — Final "result" card is visually distinct (highlighted border using PRD-002 accent token); shows: matched (yes/no), destination URL, redirect type, source row reference (clickable — closes Test tab, switches to Manage tab, opens that row's `RowEditForm`). - **FR-B8** — "No match" final card shows: candidates tried, rows considered, suggestion text ("did you mean to add a rule for this URL?")
- **FR-B9** — "Copy as JSON" footer button writes the full trace object to clipboard

The simulator's `rules` parameter contains the flattened row list from the picked map(s), with each row carrying a reference to its parent map's `RedirectType` + 3 flags (needed for flag-effect trace stages).

### Simulator library (FR-S)

- **FR-S1** — `site/lib/redirects/proxy-simulator.ts` exports a single `simulate(input)` function with signature `simulate({ url: string; locale: string; rules: RedirectRule[]; siteLanguage: string }): Promise<SimulationTrace>`. (ADR-0040 records the Promise return type.)
- **FR-S2** — The simulator replicates the upstream `RedirectsProxy` match algorithm verbatim, including the `isRegexOrUrl` `slice(0, -1)` quirk (ADR-0038)
- **FR-S3** — `SimulationTrace` is a typed object with one entry per pipeline stage (pre-filter checks, normalize, candidate generation, per-row evaluation, match resolution, substitution, flag effects, final dispatch)
- **FR-S4** — Per-row regex evaluation wraps `regex.test(candidate)` in `Promise.race([test, sleep(100).then(() => 'timeout')])`; on timeout, the row's trace entry has `outcome: 'timeout'`. (ADR-0039 records this safety choice.)
- **FR-S5** — Total simulation wall-clock is capped at 3 seconds; on cap, simulator stops and emits a final "diagnostic incomplete after 3s" trace card with counts of evaluated vs. total rows. Per AC-T2.2.
- **FR-S6** — Header comment at top of `proxy-simulator.ts` includes: upstream source URLs, commit SHA at retrieval (`<SHA>` placeholder filled by T2), retrieval date, ADR-0038 reference, list of known divergences (target: empty — see M2's 100% parity requirement)
- **FR-S7** — Simulator does NOT call any SDK or network endpoint — pure local computation against in-memory rules
- **FR-S8** — Pre-filter checks (URL contains `.`, preview-mode, prefetch) are surfaced as their own trace stage so operators can diagnose runtime-side skips. These are **informational only** — the simulator continues evaluation for diagnostic visibility (in contrast to runtime, which short-circuits).

### Pattern parity

- **FR-P1** — `lib/redirects/proxy-simulator.test.ts` is parameterized over two fixture files: `__fixtures__/upstream-cases.json` and `__fixtures__/tenant-cases.json`
- **FR-P2** — `__fixtures__/upstream-cases.json` is generated from the upstream `redirects-proxy.test.ts` and committed verbatim; regeneration is a manual step during T2 (PRD-005 will automate this)
- **FR-P3** — `__fixtures__/tenant-cases.json` contains ≥5 cases captured during T1; each case has `description`, `redirects` (current rules array), `request` (path + locale), `expected` (matched, destination, type)
- **FR-P4** — Known upstream-case divergences (if any after T2) are documented in `proxy-simulator.ts` header AND ADR-0038 — never silently skipped

## 9. Technical Considerations

### Existing context

- **Platform target:** marketplace (existing Marketplace app from PRD-000/002/003)
- **App architecture, extension points, auth model, router:** all unchanged from PRD-003; no `sitecore:marketplace-sdk-lifecycle` re-evaluation needed
- **Existing SDK surfaces in use:** `xmc.authoring.graphql` (CRUD), `xmc.preview` (Edge reads), `xmc.publishing` (PRD-003), OAuth client-credentials proxy (PRD-003 server-side route)
- **No new SDK surfaces** introduced by this PRD. Heuristic check (≥3 new surfaces → split) is not triggered.

### Upstream parity strategy

The simulator is a local port. To stay in parity:

1. **Copy verbatim, not paraphrase** — the simulator's match algorithm is an exact behavioral mirror of the upstream `RedirectsProxy.handle()` + `matchFromRedirectMapRedirect()` + `matchRedirectItemRedirect()` + `getRedirectPatternRegex()`. Variable names may differ; semantics must not. (ADR-0038)
2. **Replicate quirks** — the upstream `isRegexOrUrl()` strips the last character via `input.slice(0, -1)` before its URL-shape test. This looks like a bug but is the upstream contract; we replicate verbatim. (ADR-0038)
3. **Test against upstream fixtures** — by importing the upstream test cases as JSON, **100% parity is required** (M2). Any failing upstream fixture is either a bug to fix in our simulator OR requires an explicit ADR waiver (with rationale) before merge. Divergence is never silently skipped — failing fixtures fail CI.
4. **Capture upstream SHA at port time** — `proxy-simulator.ts` header records the exact commit SHA. PRD-005 will diff our snapshot against latest-on-`dev` to detect drift.

### Regex safety

A pathological pattern like `(a+)+$` against a long input can backtrack catastrophically and hang the browser tab. Mitigation:

- Wrap each per-row `regex.test(candidate)` in `Promise.race([test, timeout(100ms)])`
- On timeout, the row's trace entry is marked `outcome: 'timeout'` with explanatory text
- Single-row timeout does NOT abort the entire test — other rows still evaluate (the upstream proxy short-circuits on first match, but our simulator must trace all candidates for a "no match" diagnostic)
- **Total simulation wall-clock cap: 3 seconds.** Bounds the worst case on pathological inventories (e.g. 500+ rows × all-timeout = 50 seconds without the cap). On cap reached, simulator stops evaluating and emits a final "diagnostic incomplete after 3s — evaluated X of Y rows" trace card. AC-T2.2 covers the UI side.
- 100ms per-row + 3s total are generous defaults; well below operator perception threshold of "test button hung the app"
- Web Worker isolation considered but rejected — added bundle complexity does not justify the v0 use case; reconsider in PRD-006+ if catastrophic patterns become an authoring norm (ADR-0039)

### State model

- **Mode toggle state** — local component state in `RowEditForm`; not persisted; resets to Pattern on every row-edit open (FR-A2)
- **Active tab state** — local Workspace state in Full Page; resets to "Manage" on page reload (no URL state, no localStorage)
- **Test inputs** — local Test surface state; cleared on tab navigation away
- **Trace output** — local Test surface state; persisted across Manage-Test tab toggles within a single page lifecycle (operator can manage edits then re-view the last trace)
- **No Sitecore writes triggered by Test** — the surface is strictly read-only with respect to the tenant

| ADR-0039 | Regex safety via 100ms `Promise.race` per `test()` call + 3-second total simulation wall-clock cap (not Web Worker isolation) | v0 scope; Worker complexity not justified for current authoring patterns; 3s cap bounds worst case on large/pathological inventories |

**In-memory types (new):**

```typescript
// site/lib/redirects/proxy-simulator.ts (illustrative; verify against upstream .d.ts in T2)

type SimulationInput = {
  url: string;             // absolute URL or path+query
  locale: string;          // ISO locale, e.g. 'en'
  rules: ScopedRedirectRule[];   // rules from the picked maps only (NOT tenant-wide)
  siteLanguage: string;    // for $siteLang substitution
};

// Each scoped rule carries its parent map's flags so the simulator can apply flag-effects
// (RedirectType + 3 flags are MAP-LEVEL SHARED fields per ADR-0023/captured-template-matrix;
// they are NOT per-row. The simulator pulls them from the parent map at evaluation time.)
type ScopedRedirectRule = {
  source: string;
  target: string;
  rowIndex: number;
  parentMap: {
    mapId: string;
    name: string;
    redirectType: '301' | '302' | 'ServerTransfer';
    isQueryStringPreserved: boolean;
    isLanguagePreserved: boolean;
    includeVirtualFolder: boolean;
  };
};

type SimulationTrace = {
  input: SimulationInput;
  stages: SimulationStage[];   // ordered pipeline stages
  result: SimulationResult;
};

type SimulationStage =
  | { kind: 'normalize'; input: string; output: string }
  | { kind: 'candidates'; locale: string; candidates: string[] }
  | { kind: 'evaluate-row'; row: RedirectRow; mode: 'url' | 'regex'; outcome: 'match' | 'no-match' | 'skipped' | 'timeout'; capturedGroups?: string[] }
  | { kind: 'substitute'; template: string; resolved: string; substitutions: Record<string, string> }
  | { kind: 'flag-effects'; flags: { isQueryStringPreserved: boolean; isLanguagePreserved: boolean; IncludeVirtualFolder: boolean }; transformedUrl: string }
  | { kind: 'dispatch'; redirectType: '301' | '302' | 'ServerTransfer'; finalUrl: string };

type SimulationResult =
  | { matched: true; row: RedirectRow; rowMapId: string; finalUrl: string; redirectType: '301' | '302' | 'ServerTransfer' }
  | { matched: false; candidatesTried: string[]; rowsConsidered: RedirectRow[]; rowsConsideredTotal: number; diagnosticIncomplete?: { evaluatedRows: number; totalRows: number; reason: 'wall-clock-cap' } };
//                                                                                            ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
// rowMapId: opaque ID of the parent Redirect Map item; used by Test → Manage deep-link
// rowsConsidered: capped to first 20 entries; rowsConsideredTotal carries the full count
// diagnosticIncomplete: present when the 3s wall-clock cap was reached
```

## 13. Risks and Mitigations

- **R1 — Existing CRUD strips regex chars on save/read** (probability: medium, impact: high)
  - Mitigation: T1 is a probe tranche specifically to verify this; if it fails, T0 fix-first before any feature work
  - Trigger: T1 captures show `^/blog/.*$` becomes `/blog/.*` on round-trip → file as new task in front of T2

- **R2 — Simulator behavior drifts from upstream proxy after a Content SDK release** (probability: high over time, impact: medium)
  - Mitigation in this PRD: header-comment SHA + ADR-0038 documenting parity contract
  - Long-term mitigation: PRD-005 (drift detection + AI re-sync) — explicit follow-up

- **R3 — Catastrophic regex pattern hangs the tester UI** (probability: low, impact: medium)
  - Mitigation: 100ms `Promise.race` timeout (ADR-0039); never blocks tab; row gets explicit "too slow" trace entry

- **R4 — Operator authors regex in Pattern mode and is surprised at runtime** (probability: medium, impact: low)
  - Mitigation: inline hint (US-R2); does not block save (operator preference); hint copy explicitly says "runtime will treat as regex"

- **R5 — Test surface output is too dense / overwhelms operators** (probability: medium, impact: low)
  - Mitigation: trace cards are collapsible by stage; final "result" card is visually dominant; empty state pre-fills a known-good URL for onboarding
  - Operator validation: T6 smoke walkthrough confirms operator can read the trace without confusion

- **R6 — `isRegexOrUrl()` upstream quirk (`.slice(0, -1)`) is fixed in a future SDK release** (probability: low, impact: low)
  - Mitigation: ADR-0038 explicitly names this as a replicated quirk; drift detector (PRD-005) will flag the change; T2 fixture file regenerated from new upstream

- **R7 — Bundle bloat from helper UI** (probability: low, impact: low)
  - Mitigation: NFR-6 budget (≤25KB gz); snippet library is static JSON; no runtime regex parser library imported (use `new RegExp` directly)

- **R8b — Replacing inline editing with `EditRowModal` regresses existing PRD-000 CRUD UX** (probability: medium, impact: medium) — **replaces the old R8 ("RowEditForm extraction") which is now obsolete**
  - Mitigation: T3 carry-over CRUD smoke runs the full create → edit → save → re-read path against the live tenant through the new modal before mode-toggle / regex affordances are added on top; any divergence from pre-PRD-004 inline-edit behavior is fixed before T3 closes
  - Operator-visible UX change: existing operators previously could edit inline (less click-throughput); now they get a modal (more click-through but more focused). Acceptable per ADR-0043; surfaced in the auto-lite release notes

- **R9 — Scope-picker localStorage state goes stale across tenant switches** (probability: medium, impact: low)
  - Mitigation: persisted shape includes `tenantId`; on hydration the picker resets if `tenantId` mismatches the current context; FR-T7 covers the "previous selection no longer available" path for missing IDs within the same tenant
  - Tenants change rarely; this is defensive only

- **R10 — Cascading-picker UX gets clumsy when one collection has 50+ sites** (probability: low, impact: low)
  - Mitigation: `@blok/select` supports search input by default; document in T4 walkthrough that operators with many sites should use the search field. If complaints surface in T6 smoke, file a follow-up to add a recent-sites quick-pick.
