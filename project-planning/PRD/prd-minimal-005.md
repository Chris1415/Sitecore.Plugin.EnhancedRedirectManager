## Problem (one short paragraph)

The PRD-004 simulator is a verbatim local port of upstream `RedirectsProxy` with 100% fixture parity at port time, but upstream is a living codebase. Without a drift signal, the simulator's trace will silently diverge from real-tenant behavior weeks or months after ship. PRD-005 surfaces drift in the Test tab (passive, SHA-mismatch only, on-demand) and provides a dev-time Claude Code slash command in the product repo to re-port verbatim when drift is detected.

## Goal (one short paragraph)

Ship a two-layer drift system: (1) an on-demand "Check upstream" button on the Test tab that compares the locally-baked baseline SHA(s) against the upstream commits on Sitecore/content-sdk `dev` for the 2 ported files, rendering a dismissable banner if SHAs differ; (2) a `/sync-redirect-proxy` slash command in the product repo's `.claude/commands/` that fetches latest upstream, proposes a re-port patch via Claude Code's edit flow, regenerates fixtures via the existing AST extractor (ADR-0042), runs the test suite, and on accept auto-bumps the SHA in a new `__fixtures__/upstream-snapshot.json`. The snapshot JSON replaces the header-comment baseline as the source of truth and preserves PRD-004's `dev`-branch provenance in an `originalPort` audit field. Tracked branch is `dev` for v0 — original plan was `main`, but `main` does not exist on `Sitecore/content-sdk` today (architecture-time probe returned 404); promote to `main` via snapshot-JSON edit once Sitecore publishes it.

## Non-negotiables (bullets)

- **Zero AI / LLM dependency in the deployed Marketplace app.** Detection is SHA-only comparison. AI patch proposal lives EXCLUSIVELY in the dev-time slash command.
- **Zero new Sitecore SDK surfaces.** The in-app check is a single `fetch()` to `api.github.com` — no `@sitecore-marketplace-sdk/xmc` call, no Authoring GraphQL, no server-side OAuth.
- **SHA mismatch only** in-app — banner copy says "upstream changed; review the diff" NOT "drift detected", to acknowledge false positives from comment-only upstream changes.
- **GitHub API unauthenticated** in v0 — 60 requests/hour per IP is sufficient for on-demand-only traffic. PAT-based auth deferred to FO-5.2.
- **On-demand only** — no auto-check on Test-tab mount; no scheduled background check. Banner appears only after explicit "Check upstream" button click.
- **Dismissable per-session** — X-close hides for the current session; reappears on next page reload. No localStorage persistence (would risk stale dismissal hiding a new event).
- **Snapshot JSON is authoritative** — `proxy-simulator.ts` header comment becomes human documentation referencing the JSON; in-app check + slash command both read JSON.
- **Tracked branch is `dev` for v0** (amended at /architect 2026-05-22 — original plan was `main`, but `main` does not exist on `Sitecore/content-sdk` today; ADR-0044 amended in place to reflect). PRD-004 already tracks `dev`; v0 keeps that. Promote to `main` via snapshot-JSON edit (no code change) once Sitecore publishes a `main` branch with the watched files.
- **Slash command auto-bumps SHA only after fixtures regenerate + tests pass** — failed-test state leaves simulator + snapshot consistent (no half-applied state).
- **`knownDivergences[]` escape hatch** — operator can record a deliberate non-port; ADR-0038's contract preserved.
- **No CSP changes in PRD-005** — `next.config.mjs` currently sets no `Content-Security-Policy` header; in-app `fetch()` to `api.github.com` works without CSP modifications. If a future PRD introduces app-level CSP, it must include `api.github.com` in `connect-src`.
- **Snapshot SHA bump only reaches the in-app baseline after the next deploy** — the snapshot JSON is bundled at build time via static import. Operators may see the drift banner for a window between slash-command success and Vercel deploy completion (per R8).
- **Accessibility:** banner is `role="status"` (informational, NOT `role="alert"`); dismiss button keyboard-accessible; copy keyboard-reachable in Test tab tab-order.
- **Theme parity:** banner renders in light / dark / system per global theme policy.
- **Bundle delta ≤ 5KB gz** (well under PRD-004's NFR-6 budget of 25KB).
- **`/sync-redirect-proxy` runs only at dev time** — never bundled into the deployed app. Lives in product repo's `.claude/commands/sync-redirect-proxy.md`.

## Success criteria (3–7 bullets)

- **M1** — When upstream `dev` SHA for either of the 2 watched files differs from baseline, "Check upstream" surfaces the banner within 2 seconds (single sequential fetch round-trip on a typical network). (Tracked branch is `dev` for v0 per ADR-0044 amendment — see § 1 Executive Summary.)
- **M2** — When upstream SHAs match baseline, "Check upstream" surfaces an "in-sync" confirmation (with `lastChecked` timestamp) and no banner
- **M3** — Slash command end-to-end: fetch upstream → propose patch → regenerate fixtures → run tests GREEN → auto-bump SHA. Operator-driven smoke at T6: bump baseline SHA to a known-stale value; run check → see banner; run `/sync-redirect-proxy` → propose patch → accept → tests GREEN → snapshot JSON updated
- **M4** — Error states never block Test tab interaction (rate-limit, network, 404, 5xx all surface as banner state `'error'` with low-key copy + retry button)
- **NFR-1** — Bundle delta ≤ 5KB gz vs pre-PRD-005 baseline
- **NFR-2** — Other Marketplace surfaces (Context Panel + Dashboard Widget + existing Full Page) continue to function; `next.config.mjs` is unchanged (no app-level CSP introduced) — verified at T5 structural guard

## Key constraints & assumptions

- **C1 — Verbatim port discipline (ADR-0038 from PRD-004 carries forward).** When the slash command proposes a patch, it must replicate upstream semantics including quirks (e.g. `isRegexOrUrl` `.slice(0, -1)`). Operators reviewing the patch reject any "improvement" that diverges from upstream.
- **C2 — `knownDivergences[]` is the only escape valve.** If upstream introduces a change we deliberately do not port (e.g. behavior tied to a Content SDK feature this app doesn't support), it goes into `upstream-snapshot.json` as a structured entry with rationale.
- **C3 — Slash command must regenerate fixtures BEFORE bumping SHA.** The fixture file (`__fixtures__/upstream-cases.json`) is regenerated via the existing AST extractor (`npm run extract:upstream-fixtures`). The SHA bump only happens after fixture regeneration AND a green test run; failed-test state leaves both untouched.
- **A1 — `https://api.github.com/repos/Sitecore/content-sdk/...` and `https://raw.githubusercontent.com/Sitecore/content-sdk/main/...` remain stable, public, unauth-readable.** (GitHub has not changed this contract in years.)
- **A2 — `dev` branch at Sitecore/content-sdk is the de-facto default (v0 target).** Live probe 2026-05-22 confirmed `default_branch: 'dev'` on the upstream repo; `main` does not contain the watched file. PRD-005 v0 tracks `dev` to keep M1/M2 verifiable. **When Sitecore publishes a `main` branch with the watched files**, promote via a single-line snapshot-JSON edit (`branch: 'main'`) — no code change required.
- **A3 — The 2 watched files remain at current paths.** If a future Sitecore refactor renames or relocates them, the watcher 404s; recovery is an operator edit of `upstream-snapshot.json` + manual re-snapshot.
- **A4 — Operator + engineer roles are distinct.** Operators see the banner; engineers run the slash command. No mixing.
- **A5 — Patch-accept auto-bump is acceptable from audit standpoint** because the git commit (simulator edit + snapshot bump + regenerated fixtures together) is the durable record.
